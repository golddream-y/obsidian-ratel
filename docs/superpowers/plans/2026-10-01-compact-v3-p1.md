# 上下文压缩 P1：量准、移出、诊断

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 占用按实际上送计算，并用接口返回的 `prompt_tokens` 校准；最后一条用户消息之前的思考过程不再回传；已成功落库的写入参数换成占位，只保留本轮最近一次写入的正文。每次压缩决策和结果写入 breadcrumb。

**架构：** 纯函数 `measureOutbound` 与 `offloadStalePayload` 放在 core，单测覆盖。`projectView` 在 microcompact 之后对 tail 调用移出。`getContextUsage` / `tokenCount` 改用计量结果乘以会话校准系数。校准在 `agent-loop` 拿到 usage 时写入进程内 Map。breadcrumb 增加 `compact.decide` 与 `compact.result`。

**技术栈：** TypeScript、vitest、现有 `estimateTokens`、现有 breadcrumb。不新增依赖。

**所属 spec：** [S-COMPACT-V3](../specs/2026-10-01-compact-v3-design.md) 的 P1（§4.2、§4.3 的 R1/R2、§4.9）。P2–P5 不在本计划。

## Global Constraints

- 不改 `session.messages`。移出只作用于上送副本。
- 同一用户轮内、含工具调用的 assistant 思考过程必须保留（DeepSeek thinking 会 400）。
- 只移出成功写入的正文字段。`Error:` 开头的工具结果及其参数保留。
- 工具调用与结果不拆开：只替换 `toolArgs` 里的正文字段，`toolCallId` 不动。
- 正文字段集中声明，不在调用点写死散落的字段名。
- 占位面向模型，不走 i18n。
- 用户可见字符串本计划不新增。
- 注释与测试描述用中文。测试名格式：`行为 - 条件 - 期望结果`。
- 不提交与本任务无关的工作区改动。

### Task 3: 移出思考过程与已落库的写入参数

**Files:**
- Modify: `src/core/compact-project.ts`
- Test: `tests/core/compact-project.test.ts`

**Interfaces:**
- Produces:

```ts
/** 写笔记类工具。正文字段会被移出 */
export const WRITE_TOOL_NAMES = ['write_note', 'append_note', 'edit_note'] as const;
/** 参数里视为正文的字段。edit_note 的替换文本也算正文 */
export const WRITE_BODY_FIELDS = ['content', 'old_string', 'new_string'] as const;

export function offloadStalePayload(messages: ChatMessage[]): ChatMessage[];
```

规则：

1. 找到最后一条 `role === 'user'` 的下标 `lastUser`。没有 user 时 `lastUser = -1`，全部 assistant 都算「更早轮次」。
2. 思考过程：下标 `< lastUser` 的 assistant，副本上去掉 `reasoning` 字段。`>= lastUser` 的保留。
3. 写入：`toolName` 属于 `WRITE_TOOL_NAMES`，且配对的 tool 结果存在、不以 `Error:` 开头，才算成功写入。失败或尚无结果的不改参数。
4. 下标 `> lastUser` 的成功写入中，只保留最后一条的正文。其余成功写入（含 lastUser 之前的）把每个正文字段换成 `` `[written] path=${path} chars=${原字段字符数}` ``。`path` 不是字符串时省略 `path=`。非正文字段保留。
5. 返回新数组。未改动的消息保持原引用。

### Task 5: 压缩决策与结果的 breadcrumb

**Files:**
- Modify: `src/logging/breadcrumbs.ts`（`BREADCRUMB_PHASES`）
- Modify: `src/ui/chat/ChatView.svelte`（发送前判断、轮后判断、`runCompactInChat`）
- Test: `src/logging/breadcrumbs.test.ts` 若有 phase 白名单断言则补上；没有则不新增用例，以 `npm test` 里现有 breadcrumb 测试为准

**Interfaces:**
- Consumes: `plugin.breadcrumbs.mark(phase, sessionId, detail)`
- Produces: 两条 phase：`compact.decide`、`compact.result`

detail 格式（分号分隔，缺省字段省略）：

- 决策：`action=none|summary;pct=<整数>;used=<整数>;max=<整数>;source=estimate|api`
- 结果：`ok|skip|fail;reason=<短因>`

P1 的 `action` 只有 `none` 与 `summary`。移出层不单记 action，它每次投影都发生。

- [ ] **Step 1: 登记 phase**

`BREADCRUMB_PHASES` 在 `send.compact` 后增加 `'compact.decide', 'compact.result'`。

- [ ] **Step 2: 发送前与轮后打决策点**

`ChatView.svelte` 里两处调用 `decidePreSendCompact` / `decidePostTurnCompact` 之前：

```ts
plugin.breadcrumbs?.mark(
  'compact.decide',
  sessionId,
  `action=${willCompact ? 'summary' : 'none'};pct=${percentage};used=${usedTokens};max=${maxTokens};source=${source}`,
);
```

发送前：`source=estimate`，`usedTokens` 取 `preUsage.usedTokens`，`percentage` 取 `preUsage.percentage`。

轮后：有 `lastTurnApiTokens` 时 `source=api`、`usedTokens=lastTurnApiTokens`；否则 `source=estimate`，`usedTokens` 取 `postCtx.getContextUsage(maxTokens).usedTokens`。先算 usage，再算 percentage，避免算两遍。

`willCompact` 就是随后传给 `decidePreSendCompact` / `decidePostTurnCompact` 的结果。决策点在 `send.compact` 之前。

- [ ] **Step 3: 结果点**

`runCompactInChat`：

- `result.skipped`：`compact.result`，detail `skip;reason=short`
- 写完 marker 并 `succeed` 之后：`ok`
- `catch`：`fail;reason=` 加错误消息的前 80 个字符，去掉换行与 `|`（breadcrumb 以 `|` 分列）

`isCompacting || isRunning` 提前 return 时不打结果点。
