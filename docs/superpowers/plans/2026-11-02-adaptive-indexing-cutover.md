# 生产切换与跨代际复用判断

> 计划：[P-ADAPTIVE-INDEX](2026-11-02-adaptive-indexing.md) · 进度：[实施进度](2026-11-02-adaptive-indexing-progress.md) · 验收：[T9 协议](2026-11-02-adaptive-indexing-t9-protocol.md)

## 1. 跨代际复用（缺口 D）的判断

复现测试 `tests/core/index-runtime-config-switch.test.ts` 记录的现象是：切换配置后，逐字节未改的笔记被重新嵌入（`embed` 调用 1→2）。

**这不是缺陷，而是必要行为**，原因在数据本身：

- 配置指纹由 7 个字段共同决定：模型 ID、模型修订、维度、分块器版本、块大小、块重叠、嵌入文本模板。
- 其中**分块三项**（版本/大小/重叠）与**嵌入文本模板**都会改变「送进模型的文本」，因此向量必须重算。
- 只有「模型身份三项完全不变、且分块与模板也不变」时才可能复用，而这正是同一指纹的情形——同一指纹本来就复用同一代际，不会重嵌。

所以：**跨配置复用向量在数学上不成立**，不能实现，也不应实现。

真正存在的复用机会只有一个：**切回曾经用过、且代际目录仍保留的配置**。此时旧代际里已有该配置的完成记录与向量，理论上只需重新核对（输入 hash 与块集合），不必重新嵌入。当前实现走的是「新建/取回代际 + 逐文件核对」，而 `resolveIndexGeneration` 在指纹匹配时会取回该代际，所以核对应能命中已有记录；但**尚未有测试证明「切回旧配置不重嵌」**。

结论与跟进：

1. 不实现「跨配置复用向量」——不做错误的事。
2. 新增要求（记入 M2 待办）：补一条「切回旧配置不重嵌」的验收，确认 `resolveIndexGeneration` 取回路径确实命中旧完成记录；不命中则是实现缺陷，不是设计缺陷。
3. 文档与状态里不再把缺口 D 描述为「未修的复用能力」，改为「已澄清的非缺陷 + 一条待验证的切回复用」。

## 2. 生产切换的前置条件

当前生产路径仍是主线程协调器（`assembleIndexPipeline` + `IndexTaskCoordinator`）。线程版已具备：协议、宿主、会话（分块/日志/清单/Vectra/查询/恢复）、协调器、装配、代际解析、身份守卫、嵌入桥接与仲裁。

切换缺的是「可检索面」的接线，而不是索引写入：

| 面 | 现状 | 切换需要 |
| --- | --- | --- |
| 索引写入 | 线程版已可跑（客户端 + 协调器） | 用线程协调器替换 `IndexManager` 的 coordinator |
| 检索 | 主线程持有 `VectraStore` 直接查 | 改为经线程 `session.search`；`MultiQuerySearcher` 需要「查询向量来自宿主、候选来自线程」的适配层 |
| 状态/进度 | 读主线程 store/journal | 改为线程 `session.status` + 协调器 `counters()`；**可见性门已完成**：`session.listCommitted` + `createThreadVisibilityGate`（读取失败如实 `unjudgeable`） |
| 恢复 | 主线程 `recoverIndexJournal` | 改为线程 `session.recover`（已实现） |
| 降级 | 主线程装配失败路径 | 线程启动失败要映射到既有「索引暂不可用」状态 |

## 3. 切换步骤（建议顺序，每步独立提交）

1. **查询适配层**（已完成）：`MultiQuerySearcher` 新增 `candidateSource` 端口；缺省仍走 Worker，提供端口时走端口，错误语义与 Worker 失败一致（返回空而不是抛出）。18 个用例通过。
2. **线程实现该端口**（已完成）：`session.searchVector` + 客户端 `searchByVector` + `createThreadCandidateSource`；文档级标识用路径，空路径命中丢弃，线程失败上抛由编排层按同一语义处理。
3. **切换装配点**：`main.ts` 增加开关（默认关闭），装配失败回落到主线程并如实提示；身份守卫已就位。**组合验证已完成**：`tests/core/index-thread-e2e.test.ts` 用真实组件跑通「线程写入两篇 → 宿主候选来源 → MultiQuerySearcher 检索命中」，并断言召回不经过 Worker。
4. **默认开启**：宿主实测通过（T9 正确性 + 流畅度）且效率不劣化后，才把默认值改为线程版。
5. **清理**：主线程协调器保留为降级路径或删除，由实测结论决定。

## 4. 风险

- 检索面是用户主路径，适配层必须先在主线程实现上跑通再切，避免「两套查询语义」。
- 线程版没有主线程 store，「部分可用」语义（已提交即可检索）要靠线程内读数，不能沿用主线程可见性视图。
- 体积：线程包会把会话/Vectra 代码带进产物（实验包 19 MB），生产开启后需测量启动与内存。
