# P-COMPACT-V3-P1F — R2 移出层收尾:apply_patch 入表 + 正文字段登记表化

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:test-driven-development 按 RED-GREEN-REFACTOR 实施。

**目标:** 修复 P1 落地后、1.0.0 新增 `apply_patch` 带来的 R2 漂移:旧轮补丁正文每轮全量回传且计入占用;同时把写工具正文字段从两个并行硬编码常量收敛为一张登记表。

**所属 spec:** [S-COMPACT-V3](../specs/2026-10-01-compact-v3-design.md) §4.3 R2、§5 P1F(2026-10-11 复核新增)

**背景事实(已核实):**
- `src/core/compact-project.ts` 现有两个并行常量:`WRITE_TOOL_NAMES = ['write_note','append_note','edit_note']`、`WRITE_BODY_FIELDS = ['content','old_string','new_string']`。1.0.0 加入的 `apply_patch` 两个都不在。
- `stripWriteBody` 对任意写工具删「全部」`WRITE_BODY_FIELDS`——字段未按工具区分(当前侥幸无害)。
- 计量链已正确:`measureOutbound(this.toMessages())` → `projectView` → `offloadStalePayload`,入表后计数自动排除。
- 两个常量无外部 import,改动面只在本文件与测试。

## Global Constraints

- TypeScript strict;中文注释;禁止 TS enum;登记表用 `as const satisfies Record<string, readonly string[]>`(AGENTS.md「枚举与 ID 集中管理」)。
- 占位文本面向模型,不走 i18n;沿用现有 `OFFLOAD_WRITE_NOTE`。
- 不改 LLM 可见的 `ToolDefinition`(发往模型的 schema 不混入客户端元数据,spec §4.3 2026-10-11 修订)。
- 不扩大范围:不动触发阈值(P2)、不动工作集(P4)。

**Files:**

**Step 1 — RED。** 在 `tests/core/compact-project.test.ts` 追加用例(描述用中文「行为 - 条件 - 期望结果」):

1. `offloadStalePayload - 旧轮 apply_patch 成功 - 删除 patch 字段并在结果附正文提示`:构造 messages = [assistant(tool_calls apply_patch,toolArgs 含超长 `patch` 字符串,toolCallId='c1'), tool(role='tool',toolCallId='c1',content='path: x.md ...' 成功 JSON), user('下一轮')]。期望输出 assistant 的 toolArgs 不含 `patch` 且保留 `path` 等其余字段;配对 tool 消息 content 末尾含 `OFFLOAD_WRITE_NOTE` 文本。
2. `offloadStalePayload - 最后一条 user 之后的 apply_patch - 保留 patch`(最近一次写入不折,沿用 keepFullBodyIndex 语义)。
3. `offloadStalePayload - apply_patch 结果为 Error - 不移除 patch`。
4. `offloadStalePayload - 旧轮 write_note - 只删 content,不动其他字段`;`edit_note - 删 old_string/new_string`(锁按工具取字段)。
5. 登记表自检:`WRITE_BODY_FIELDS_BY_TOOL` 的 keys 包含 write_note/append_note/edit_note/apply_patch 四项,`apply_patch` 对应 `['patch']`。

先看测试失败:`npx vitest run tests/core/compact-project.test.ts`。

**Step 2 — GREEN。** 改 `src/core/compact-project.ts`:

```typescript
/**
 * 写工具正文字段登记表 — 工具名 → 成功落库后上送时可移出的参数字段。
 *
 * 关键路径:S-COMPACT-V3 R2。新增写工具必须在此登记正文字段,
 * 否则旧轮正文会每轮全量回传且计入 measureOutbound。
 * 不挂进 ToolDefinition:那是发往模型的 schema,不混入客户端元数据。
 */
export const WRITE_BODY_FIELDS_BY_TOOL = {
	write_note: ['content'],
	append_note: ['content'],
	edit_note: ['old_string', 'new_string'],
	apply_patch: ['patch'],
} as const satisfies Record<string, readonly string[]>;

const WRITE_TOOLS = new Set<string>(Object.keys(WRITE_BODY_FIELDS_BY_TOOL));
```

- 删除旧的 `WRITE_TOOL_NAMES`、`WRITE_BODY_FIELDS`、`WRITE_TOOLS` 三行(被新登记表取代)。
- `stripWriteBody(msg)` 改为按 `msg.toolName` 查 `WRITE_BODY_FIELDS_BY_TOOL[msg.toolName]`,只删该工具登记的字段;查不到则原样返回(防御,理论上 isSuccessfulWrite 已挡)。
- 其余逻辑(`isSuccessfulWrite`、keepFullBodyIndex、结果附提示)不动。
