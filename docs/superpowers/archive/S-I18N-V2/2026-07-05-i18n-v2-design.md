# i18n v2 设计 — 中英文界面切换 + 扩展性约束

> 日期: 2026-07-05
> 状态: Active
> 取代: [S-I18N](2026-06-14-ratel-i18n-design.md)(已 Superseded)
> 关联: AGENTS.md § 文档与注释规范 § i18n 强制规则

---

## 1. 背景

S-I18N 已严重过时:估算 ~50 key(实际 ~300),覆盖 3 个文件(实际 15+),假设旧 `display()` API(已迁移到声明式 `getSettingDefinitions()`)。代码库审计发现 10 类硬编码用户可见字符串,中英混用现象普遍。

本 spec 不仅覆盖当前迁移,还建立**扩展性约束**:后续所有新增功能 / spec 必须走 i18n,禁止硬编码用户可见字符串。

## 2. 目标

- 用户在设置面板切换 `auto` / `中文` / `English`
- 切换瞬时生效(`tNow` 同步读,`t` 订阅 store)
- 默认 `auto`,onload 时根据 `navigator.language` 解析
- **全 UI 覆盖**:Settings + Chat + Status + Diagnostics + Modals + Slash commands + Tool display names + Notices + 用户可见 Errors
- **扩展性**:翻译表开放式,新功能只需加 namespace key,不需改基础设施

## 3. 非目标

- 仅支持中 / 英两种语言(其余 fallback 到 en)
- 不监听 `navigator.language` 运行时变更 — 'auto' 只在 onload 解析一次
- **不翻译 LLM 内容**:
  - Prompt section 正文(`prompts/defaults/zh.ts` 的 system prompt / tool description 主体)— v1 保持中文,切英文影响 RAG 行为需单独验证
  - 但 `prompts/sections.ts` 的 label / description(设置面板展示用)走 i18n
  - 检索结果外框(`composer.ts` 的 `SEARCH_RESULTS_WRAPPER_PREFIX`)走 i18n(用户可见)
- 不做命令名运行时热更新 — `addCommand` onload 一次性注册
- 不做翻译贡献流程

## 4. 详细设计

### 4.1 模块边界

```
src/i18n/
  types.ts          # Strings interface — 开放式,按 namespace 扩展
  zh.ts             # 中文翻译表
  en.ts             # 英文翻译表
  index.ts          # store + t + tNow + detectLang + applyLangPreference
  strings.test.ts   # 翻译表完整性(key 对齐 / 非空)
  index.test.ts     # 运行时行为(detect / setLang / 插值 / store 发射)
```

### 4.3 关键 API

```typescript
// index.ts
export type Lang = 'zh' | 'en';
export type LangPreference = 'auto' | 'zh' | 'en';

export const langStore: Writable<Lang>;          // 响应式 store
export function t(key: keyof Strings, params?: Record<string, string | number>): string;  // 订阅 store
export function tNow(key: keyof Strings, params?: Record<string, string | number>): string;  // 同步读
export function detectLang(): Lang;
export function applyLangPreference(pref: LangPreference): Lang;
export function setLang(lang: Lang): void;
```

### 4.4 翻译表扩展规则

新功能加 key 时:
1. 在对应 namespace interface 加 key 类型声明(如 `MemoryStrings`)
2. 在 `zh.ts` 加中文值
3. 在 `en.ts` 加英文值
4. 在 `strings.test.ts` 自动校验 key 对齐(已有测试)

**禁止**:直接在代码里写中 / 英文字面量。

## 5. 扩展性约束(长期硬约束)

> 本节是 spec 的核心约束,适用于**所有后续功能 / spec / plan**。

### 5.1 强制规则

所有新增功能的用户可见字符串**必须**走 `t('key')` / `tNow('key')`,禁止硬编码。

**用户可见字符串定义**:
- Settings 面板的 `name` / `desc` / `heading` / `action` 文案
- Chat UI 的 placeholder / button / aria-label / 标题
- Notice / Modal 文案
- Status bar / Drawer 标签
- Slash command description
- Tool display name(format-tool-display 友好名)
- 用户路径上的 throw new Error 消息

**例外**(不需 i18n):
- 面向开发者的 `console.*` / `devLogger.*`(AGENTS.md § 1 规定中文)
- LLM 收到的 prompt 正文(`prompts/defaults/zh.ts`)
- LLM 收到的 tool schema description
- 代码注释
- 错误堆栈(stack trace)

### 5.2 触发时机

任何 `feat` / `fix` commit 含新用户可见字符串时:
1. 实现者在 `src/i18n/zh.ts` + `en.ts` 加对应 key
2. 代码里调 `t(...)` / `tNow(...)`
3. 不允许提交含硬编码用户可见字符串的代码

### 5.3 审查机制

- **subagent-driven-development spec 审查阶段**:检查硬编码字符串
- **代码 review**:`requesting-code-review` 技能检查 i18n 合规
- **自动化**:未来加 ESLint 规则检测 `.svelte` / `.ts` 中的硬编码中英文字面量(v1 靠规则约束,v2 加 lint)

### 5.4 翻译表开放性

`Strings` interface 用 namespace 扩展(`extends A, B, C`),新功能只加 namespace,不改基础设施。`zh.ts` / `en.ts` 用对象 spread 合并:

```typescript
// zh.ts
export const zh: Strings = {
  ...baseZh,
  ...settingsZh,
  ...chatZh,
  ...memoryZh,
  // 新功能追加
};
```
