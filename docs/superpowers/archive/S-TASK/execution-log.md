## 2026-08-22 — spec 取代归档(Superseded,未实施)

**取代关系:** 被 [S-GOAL](../../specs/2026-08-22-agent-goal-mode.md)(Agent 目标模式)取代,替代者同日立项。

**原因(用户决策 + 设计复盘):**

1. **「计划先行」前提不成立**:动态工作流下 LLM 每轮按最新观察重新规划,预声明的 `{text, done}` 步骤清单既不是模型的决策依据,也不是可靠的恢复载体——task JSON 不存游标与中间产物,恢复的是计划骨架而非工作现场
2. **笔记插件的本质优势是「库本身就是持久状态」**:剩余工作可从库里重新推导(哪些笔记还缺 frontmatter 是可查询事实),不需要 checklist 记账
3. **行业调研收敛于 goal 三件套**(意图 + 完成标准 + 预算):Claude Code TodoWrite 仅作会话内透明层;Copilot coding agent 把状态外置到 issue/repo;Manus 用 todo.md 做上下文锚而非状态机——静态任务清单正被动态工作流普遍替代
4. **长任务真瓶颈在执行侧**(逐笔权限确认、token 成本),不在任务记账;S-TASK 未触及该瓶颈

**继承进 S-GOAL 的资产:**

- onload 恢复提示时刻(「有未完成的事,继续吗?」)
- 全局单活的防混理由(原 D1 → S-GOAL D1,扩展为单活 + pending 队列)
- 终态不静默删除的原则(原 GC 反思 → S-GOAL D4,确认后归档)
- 落盘位置与原子写、损坏即弃的健壮性思路

**未实施:** 无任何代码产出(spec 立项三天内被设计复盘取代)
