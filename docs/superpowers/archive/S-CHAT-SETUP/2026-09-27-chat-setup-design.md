# S-CHAT-SETUP — 对话模型设置收成一套

> 日期: 2026-09-27
> 状态: Active
> Spec ID: **S-CHAT-SETUP**
> 关联: [S-CHAT-PROFILES](2026-09-24-chat-profiles-design.md)（多套配置与顶栏菜单）、[ADR-007](../../adr/2026-06-28-model-context-window-registry.md)（窗口映射表）、[S-CONTEXT-ACCURACY](2026-09-24-context-accuracy-design.md)

## 1. 背景

「对话模型」这一页现在同时有：场景预设、已保存的配置、模型名、API 地址、密钥。上下文长度却在「高级」里，又是一档下拉（128k / 256k / 1M / 自定义）加一个 token 数字，改模型时映射表还会再写一遍。三套控件描述同一件事，手改和自动填写互相覆盖。

Continue、Open WebUI、Cline、Cursor 的共同做法是：提供商、模型名、窗口长度属于同一条配置。认识的模型，窗口自动填上；自定义地址才手填。没有一个和模型并列的全局「上下文档位」。

仓库里聊天稿在 `docs/prototype/chat-ui-mockup.html`。对话模型这一页的顺序稿在 `docs/prototype/settings-chat-setup.html`，用浏览器打开，不嵌进对话。

## 2. 目标

1. 对话模型页只编辑「正在用的那一套」。提供商、模型名、上下文长度按这个顺序排，不再分到两个页。
2. 选 DeepSeek 或 Ollama 时，地址写死，地址框不出现。只有自定义才填写地址。
3. 上下文长度默认是查到的窗口，一行字说明。查不到，或用户要故意用得更小，才出现数字。
4. 已保存配置的列表和顶栏菜单仍然用来切换整套。嵌入和重排不进这一套。

## 3. 非目标

- 不在设置里做「提供商 → 模型目录」的两级清单。模型名仍是一个输入框；接口能列出模型时再改成下拉，本 spec 不做拉取。
- 不把嵌入、重排收进对话配置。
- 不改顶栏菜单的样子（见 S-CHAT-PROFILES CP-08）。
- 不重做五个顶栏的名字和顺序（对话模型、笔记索引、记忆与权限、外观、高级）。
- 不把密钥写进 `data.json`。密钥只出现在展开的那一套上，不在每一行都放一个密码框。

## 4. 需求

| ID | 需求 | 验收口径 |
|---|---|---|
| CS-01 | 只编辑当前套 | 对话模型页上的提供商、模型名、窗口，改的是 `activeChatProfileId` 那一套，并同步当前四个展开字段 |
| CS-02 | 提供商决定地址是否可见 | DeepSeek、Ollama 不显示地址框，地址用现有常量。自定义才显示地址。手改地址视为自定义 |
| CS-03 | 窗口一行 | 查到映射时，显示「这个模型的窗口是 N」，不出现 128k/256k/1M 下拉。用户把数字改得比查到的更小后，这一套记 `windowUserSet`，模型名不变时不再被查表盖掉。数字不能大于查到的窗口 |
| CS-07 | 长设置进二级页 | 工具权限从「记忆与权限」点进单独一页。映射表、对话里改其他插件、提示词覆盖、记忆上限、开发者、诊断从「高级」点进各自一页。这些页里的字段与现在一致，只是不铺在主页上 |
| CS-04 | 查不到才手填 | 映射表没有这个模型时，出现数字框，并沿用现有「未查到窗口」提示。不静默保留上一个模型的上限 |
| CS-05 | 高级页不再放窗口 | 「高级」里的上下文档位、探测按钮、自定义 token 从该页移除，避免和第二处打架 |
| CS-06 | 场景预设不再单独成组 | 现有「场景预设」下拉去掉。提供商下拉取代它。旧数据里的 `chatPreset` 仍能读，打开设置时反映到提供商 |

## 5. 详细设计

### 5.1 页上的顺序

对话模型页，从上到下：

1. 已保存的配置。点中的那一行下面立刻展开这一套的名称、提供商、模型名、上下文长度，用缩进和左边一条线挂在它下面。未选中的行不展开。另存在列表下方。
2. 其余与模型无关的对话选项（语言、压缩开关等）留在原位，不插进展开的这一套里。工具权限、映射表、提示词覆盖、记忆上限、开发者、诊断各占一个二级页，从「记忆与权限」或「高级」点进去，不铺在主页上。

### 5.2 提供商

| 提供商 | 地址 | 模型名 | 密钥 |
|---|---|---|---|
| DeepSeek | `https://api.deepseek.com`，不展示 | 默认 `deepseek-v4-flash`，可改 | 要 |
| Ollama | `http://localhost:11434/v1`，不展示 | 默认 `llama3.2`，可改 | 不要 |
| 自定义 | 显示地址框 | 手填 | 非本机地址要 |

从 DeepSeek 或 Ollama 改成另一个提供商时，地址和默认模型按上表写入当前套。只改模型名、不改提供商时，地址不动。

提供商不另存字段。由这一套的地址判断：官方 DeepSeek 地址是 DeepSeek，本地 Ollama 地址是 Ollama，其余是自定义。`chatPreset` 跟着这个判断写入，界面上不再有单独的场景预设下拉。

### 5.3 上下文长度

换模型名或换提供商之后查映射表：

- 查到：这一套的上限写成该数，页上只显示这句话，不给档位下拉。
- 查不到：显示数字框，提示未查到。
- 用户改小数字：这一套 `windowUserSet` 为 true，上限写成该数，且不得大于本次查到的窗口。模型名不变时，再次打开设置不再查表覆盖。
- 用户又改了模型名或提供商：`windowUserSet` 清掉，重新查表。查到就用新窗口；查不到就清空旧上限并露出数字框。

百分比和自动压缩继续用这个上限。不把各步 token 加总写进这个数。

### 5.4 和现有控件的关系

`chatPreset` 不再出现在界面上。存盘仍可写，便于旧库打开。`contextLengthPreset` 的 128k/256k/1M 档位从界面去掉；内部可以用 `custom` 加上 `chatModelMaxTokens` 表示「这一套自己的数」。

声明式设置画不下「点中一行再展开」。已保存配置、提供商、模型名、窗口说明放在现有单独拼上的那一块里。声明式定义里删掉场景预设组，以及高级页主层上的窗口组。

### 5.5 二级页

Obsidian 设置已经能进子页（诊断就是这样）。主页只留入口，点进去是整页，有返回。

| 入口所在 | 二级页 | 页内仍是现在这些字段 |
|---|---|---|
| 记忆与权限 | 工具权限 | 每个工具允许 / 询问 / 拒绝 |
| 高级 | 模型映射表 | 地址、恢复默认 |
| 高级 | 对话里改其他插件 | 一个开关 |
| 高级 | 提示词覆盖 | 按段编辑、预览、恢复本段 |
| 高级 | 记忆上限 | 磁盘、注入、动态段、上下文合计、相关主题条数 |
| 高级 | 开发者 | 调试日志、崩溃记录、单轮最大步数、技能脚本超时 |
| 高级 | 诊断 | 现有诊断页，不改里面的三个子栏 |

笔记索引、外观、目标、记忆开关、日记、库外开关、MCP 按钮留在各自主页，不进二级页。

## 6. 影响面

| 区域 | 变化 |
|---|---|
| 对话模型页 | 提供商、模型名、窗口收到当前套下面；场景预设组删除 |
| 高级页 | 主层只留二级页入口。窗口档位、探测、自定义 token 从主层删除 |
| 记忆与权限 | 工具权限改为入口，页内字段不减 |
| 已保存配置 | 仍负责切换、另存。密钥只在展开的那一套上 |
| 顶栏菜单 | 不改 |
| 测试 | 选 Ollama 不出现地址；换模型名会查表；改小之后同模型不再被查表盖掉；高级页无窗口控件 |
