# S-AGENTS-INJECT — 目录约束注入上下文，不再拦住第一次修改

> **ID:** S-AGENTS-INJECT
> **状态:** Active
> **日期:** 2026-10-02
> **取代:** [S-AGENTS-GATE](2026-10-01-agents-gate-design.md) 的「第一次不执行、返回 Error」做法。库根每轮注入保持不变。

---

## 1. 背景

子目录里的 `AGENTS.md` 现在靠工具闸门交给模型：本轮第一次碰到某条路径时，写入、删除、移动、复制都不改文件，把整篇约束当作工具结果返回。移动还对原路径和目标路径各拦一次，提示却说「相同参数再调一次就会执行」。第二次常常撞上另一条还没见过的路径，于是再失败一次。

模型会把这段结果理解成文件被锁、通道异常或同名冲突。同名冲突是另一条错误（「目标已存在，未覆盖」），和第 4 章那次移动无关。

Claude Code 的公开实现是：`CLAUDE.md` 拼进每一轮提示，访问子目录时再加载该目录的规则。工具该执行就执行，不用失败一次来完成阅读。

库根 `AGENTS.md` 已经在每轮记忆段之后注入。缺的是子目录规则的注入方式。

---

## 2. 目标

1. 写入、追加、替换、删除、移动、复制的第一次调用就执行。
2. 碰到一条路径时，把该路径到库根的 `AGENTS.md` 链注入本轮上下文，同一条目录链本轮只注入一次。
3. 工具结果只描述这次操作本身。约束不再出现在工具结果里。
4. 移动和复制失败时，只报磁盘上的真实原因，与约束无关。

---

## 3. 非目标

- 不取消库根每轮注入。
- 不自己改写笔记里的链接。移动仍走 `FileManager.renameFile`。
- 不对「是否同一份内容」做 hash 比较。目标已存在就拒绝覆盖。
- 不提高输出长度上限，不改变压缩。

---

## 4. 调整哪些

| 现在 | 调整后 |
|---|---|
| `applyNoteAgentsGate` 在写路径上可以 `proceed: false`，返回 `Error: 未改动文件` 加整篇约束 | 删除这条失败路径。写操作始终执行 |
| `move_note` 对 `from` 和 `to` 各走一次闸门 | 两次都只负责注入对应目录链，然后调用 `renameFile` |
| `read_note` 把约束放进 `agentsConstraints` | 读到的正文仍只在 `content`。约束改由上下文注入，不再附在读结果里 |
| 模型要靠失败结果才看见子目录规则 | 规则在当轮后续请求的上下文里，靠近现有库根约束 |

注入内容沿用现有目录链：从笔记所在目录到库根，近的在后，字节上限不变。库根那一层已经每轮注入，子目录注入时不要再重复库根全文。

「本轮见过」改成按目录链去重，不按完整文件路径。同一文件夹里移动第 2 章和第 4 章，链相同就只注入一次。

### 移动和复制的结果

成功返回 `{ from, to }`。失败时 `Error:` 后面只写下面一种原因，不附 `AGENTS.md`。

| 实际情况 | 返回 |
|---|---|
| 原路径没有这个文件或文件夹 | 原路径不存在 |
| 目标路径已经有文件或文件夹 | 目标已存在，未覆盖 |
| 原路径和目标路径相同 | 原路径和目标路径相同 |
| 目标的父目录不存在 | 不是失败。先建父目录，再移动或复制 |
| Obsidian 移动或复制抛错 | 把接口的错误原文附上 |

父目录不存在会先建，所以不会报「目标目录不存在」。同名就拒绝，这次不比较两份内容是否相同。

---

## 5. 影响面

| 区域 | 变化 |
|---|---|
| `src/tools/note-agents.ts` | 闸门改为「收集尚未注入的目录链」；不再返回拦住用的 `Error:` 文本 |
| `write_note`、`append_note`、`edit_note`、`delete_note`、`move_note`、`copy_note`、`read_note` | 调用收集函数后继续执行 |
| 上下文组装 | 本轮新出现的子目录约束写入会话上下文，下一次模型请求能看见 |
| 测试 | 第一次 `move_note` 就移动成功；同一目录链不重复注入；原路径不存在、目标已存在、路径相同各自返回对应错误；父目录不存在时会创建；读结果不含整篇 `AGENTS.md` |
| CHANGELOG | 一条：改某个目录里的笔记时，第一次就会执行，规则出现在上下文里而不是失败结果里 |
