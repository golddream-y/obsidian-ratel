# 索引执行隔离与自适应调度变更范围

Spec ID：`S-ADAPTIVE-INDEX`。需求：`BUG-1-INDEX-PERF-001`；在 [Project](https://github.com/users/golddream-y/projects/1) 草稿跟踪，未创建公开 Issue。

本文件界定本次变更范围和验收；总体机制以[索引执行与存储架构设计（提案）](../../architecture/proposals/2026-11-02-index-runtime.md)为准。2026-11-02 按用户委托完成 spec 自审并关联 [P-ADAPTIVE-INDEX](../plans/2026-11-02-adaptive-indexing.md)（Pending）；实施从真实线程可行性验证开始，本轮不启动源码实现或发布。

## 背景

1.3.0 已支持逐文件续建，但主线程仍承载分块、向量校验和 Vectra 整库 JSON 序列化。用户明确卡顿对象为 Obsidian 客户端，因此不能仅用降低平均 CPU 或增加批间休息作为修复完成条件。

## 目标

- 将索引重计算与唯一存储视图隔离到真实独立线程，保持界面响应。
- 维持文件级持久提交、配置代际、取消交接与崩溃恢复。
- 在线程隔离成立后，用自适应调度降低持续后台占用。

## 非目标

本次不更换 Vectra、不引入原生模块，不承诺整机 CPU 百分比，不同时改为分片数据库，不取消校验或耐久提交，不对生产库做开发预览。

## 交付优先级

本次交付目标是**索引期间 Obsidian 能正常使用**：输入、滚动、切换笔记与查询不被索引阻塞，且正确性与效率不回退。按此拆为两个里程碑：M1 为线程隔离与可靠性收口（T0 → T-REL → T1～T6 → T9），M2 为自适应调度与速度模式（T7、T8、T10）。M2 后置，不以调速完成替代 M1。

M1 开始前必须先收口上一计划的可靠性缺口（派生清单恢复、配置切换语义、flush 一致性等）；这些机制在现役内核上以复现测试固定后，再原样迁入独立线程，避免迁移时丢状态或重复计算。承接关系见 [P-ADAPTIVE-INDEX](../plans/2026-11-02-adaptive-indexing.md) 的「遗留项承接映射」。

## 详细设计入口与边界

| 决策 | 设计依据 | 本次约束 |
| --- | --- | --- |
| 线程与模块 | 架构提案「索引总体设计」「模块与运行边界」 | 宿主保留 API/UI；独立索引线程负责重计算与存储；既有嵌入线程负责模型 |
| 数据与存储 | 架构提案「存储、恢复与配置」 | 复用当前检查点；线程迁移不构成重建理由；不保留两套权威索引 |
| 查询与故障 | 架构提案「查询、背压与故障」 | 有界消息、批次/文件边界仲裁、可靠终态和单写入者 |
| 自适应调度 | 架构提案「信号、有效性与降级」「自适应策略」 | 信号缺失保守；不让速控破坏内容与提交语义 |
| 实施顺序 | 架构提案「验证顺序与交付判断」 | 先真实线程能力与界面响应，再恢复/查询，最后自动调速 |

## 验收

验收分三组，互不替代：**正确性**（V3、V5、V8 及未变文件零重复嵌入）、**流畅度**（V1、V2、V4）、**效率**（V7 与 T9 门槛）。界面不卡不能证明正确性或写放大已解决；吞吐提升不能证明交互不被阻塞。

| 编号 | 通过条件 |
| --- | --- |
| V1 | Sandbox 中真实独立 Worker 运行，非 InlineWorker 模拟；具备所需 Node/文件能力及构建支持 |
| V2 | 分块、hash、向量校验及大 JSON 提交不在 UI 线程执行；通过输入/滚动响应对照确认改善 |
| V3 | 每代际一份权威存储视图，不跨线程复制全库；消息条数与字节背压可验证 |
| V4 | 查询能在提交边界获得服务；索引大文件不永久阻塞交互队列 |
| V5 | 取消、卸载、崩溃和重启保持单写入者、receipt/revision 一致；未改文件零重复嵌入 |
| V6 | 真实模型的批次调速、压力降档、信号缺失及手动暂停符合架构提案 A1～A8 场景 |
| V7 | 整库 JSON 写放大仍单列测量；未关闭的存储或响应问题不得被吞吐提升掩盖 |
| V8 | 关闭自动索引后 Worker 仅只读打开可信存储，无写锁/初始化/恢复/迁移/扫描/自动模型请求；显式查询仍可用，切换写模式不双开存储 |

各项仅为待实施验收，不是已有测试结果；当前只完成文档整理与设计。

## 自审结论

独立审查确认方向与架构映射成立，无方向性阻断；补齐了 3 项影响：可序列化 grant 与提交 ticket、Vault 代理不承担主线程 hash、只读初始化与显式查询边界。复核时发现关闭自动索引不发模型请求的旧文案与显式查询冲突，已限定为「不发自动索引请求」。主代理裁定 spec 可进入 plan；Worker 平台能力和 V1～V8 运行验收均未执行。
