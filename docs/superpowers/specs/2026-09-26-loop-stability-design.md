# S-LOOP-STABILITY — 一轮对话不要无声停住

> 日期: 2026-09-26
> 状态: Active
> Spec ID: **S-LOOP-STABILITY**
> 关联: [agent-loop](../../../src/core/agent-loop.ts)、[S-RUN-STATUS](2026-09-26-run-status-design.md)（跑起来时怎么说，另 spec）

---

## 1. 背景

用户看到的「干到一半停了」，多数不是界面卡死，而是这一轮从某个出口结束了，出口没有说人话。

现有循环里，这些出口是真的：

- 默认最多 50 步。到顶后补一句上限说明，但前面已经像正常写完。代码注释写的就是「跑到一半停了」。
- 某一步没有文字、没有工具，整轮就当答完。前面如果已经调过工具，这一步空返回会把没收尾的工作切掉。
- 接口错误会停整轮。这是对的。工具自己失败会把错误交回模型再想。这也是对的。
- 读笔记、检索、装插件没有统一超时。本机命令自己有 30 秒。一个不返回的工具会让这一轮一直等，球还在转。

取消已经接上：停止会断开流式请求，还没开始的工具不再开。正在跑的那一个会跑完。这个不改。

## 2. 目标

1. 步数快用完时，先让模型收束，而不是突然切断。
2. 已经做过工具、下一步却是空的，自动再给模型一次机会把话说完。只给一次。
3. 工具挂住时，这一轮继续，模型收到「超时」，而不是永远停在转圈。
4. 到顶、超时、空步续写，用户都能看见一句明白的话。不靠开发者日志。

## 3. 非目标

- 不把默认 50 步调大，也不在到顶后自动加步。
- 不改现有的接口重试（抖动、限流、还没出字之前的重试）。
- 不改停止钮的语义。
- 不处理「有一行短正文、思考更长、然后正常结束」。那是收笔护栏，见 [S-TURN-CARRY](../archive/S-TURN-CARRY/2026-09-26-turn-carry-design.md) 与 [ADR-020](../../adr/2026-09-27-turn-completion-guard.md)。
- 不给每个工具各写一套超时。循环只有一个兜底；工具自己已有更短超时的，以它自己的为准。
- 不在这一 spec 里改状态文案。文案见 S-RUN-STATUS。

## 4. 需求

| ID | 需求 | 验收口径 |
|---|---|---|
| LS-01 | 步数将尽时提醒模型收束 | 剩余 5 步时，下一次模型请求多一段系统说明：先收束回答，不要再开新的工具链。用户气泡里看不见这段 |
| LS-02 | 到顶时用一句话结束 | 走到 50 步仍停不住时，助手消息里有一句「这一轮步数用完了，可以让我接着做」。不出现未翻译的 Error 前缀。红条与这句话不各说一遍 |
| LS-03 | 空步只续一次 | 本轮已经执行过至少一个工具，下一步没有文字、没有思考、没有工具：自动再请求一次，并说明根据已有结果把话说完。同一轮最多一次。第一步就是空的，仍按现在结束，不续 |
| LS-04 | 工具兜底超时 | 没有自己超时的工具，执行超过 60 秒视为失败。结果是给模型的工具错误「超时」，循环继续。本机命令仍是它自己的 30 秒 |
| LS-05 | 停止仍能打断等待 | 超时等待中点停止，不再等满 60 秒。已取消不记成超时 |

## 5. 详细设计

### 5.1 步数

`effectiveMaxSteps` 仍来自设置，默认 50。当 `step >= effectiveMaxSteps - 5` 且还没到顶时，这次 `llm.chat` 的消息末尾追加一条 `system`：请用剩下的步数收束，不要再开始新的多步工具。这条不写入会话存档，避免下一轮用户还看见。

到顶时只走一条用户可见出口：助手正文末尾一句 i18n。不再同时 `yield error LLM_ERROR` 和一段硬编码中文。开发日志可以留。

### 5.2 空步

在「没有 toolCall 就当最终回答」之前判断：本轮 `step > 0` 或本轮已经成功/失败执行过工具，且本步 `accumulatedText`、`accumulatedReasoning`、`toolCalls` 都空。满足则 `step` 不结束循环，下一次请求前插入一条不落盘的 `system`：上一步没有产出，请根据已有工具结果继续回答，或说明做不到。用一个回合内计数，达到 1 次后不再续，按正常结束。

第一步就空：保持现在的结束。不把空回复当成故障重试。

### 5.3 工具超时

循环在 `tools.execute` 外包一层：`AbortSignal` 与 60 秒定时器，谁先到听谁的。用户取消走现有 `CANCELLED`。定时器先到则 `TOOL_ERROR`，`result` 为超时说明，钩子走 `post-tool-failure`，然后继续下一个工具和下一模型步。

`run_host_command` 内部已是 30 秒。兜底 60 秒不会先于它开火。不要再包一层更短的超时。

超时文案走 i18n，给模型的工具结果用同一句中文或当前界面语言的短句，不带堆栈。

## 6. 影响面

| 区域 | 变化 |
|---|---|
| `src/core/agent-loop.ts` | 收束提示、空步一次续写、到顶文案、工具超时 |
| `src/i18n` | 收束句不进界面；到顶句、超时句、空步说明 zh/en |
| 测试 | 剩余 5 步才插入收束；到顶只有一句；空步续一次、第一步空不续；超时后循环仍能再走一步；取消不等满超时 |
