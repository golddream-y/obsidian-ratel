# 状态抽屉索引区版面收敛设计

> 2026-11-06。范围：`StatusDrawer.svelte` 的「知识库索引 / 上下文」两区，仅展示层，不改状态语义、不动数据口径。

## 问题

同一份进度数据被重复表达 4 次：`已索引 8 / 97 篇`、`已完成 8.2%`（8÷97）、`剩余 89 篇`（97−8）、`失败 0 篇`（恒为 0 的噪音）。另有两级标题、两处进度条、状态栏「索引中…」叠加，有效信息密度低。

## 目标

- 每个事实只出现一次；
- 索引区与上下文区视觉节奏一致；
- 不改变任何状态判定、进度计算、完成语义；
- 不新增功能、不新增依赖。

## 设计

### 信息层级（单一事实源）

| 事实 | 唯一呈现位置 |
| --- | --- |
| 状态是什么 | `.ratel-index-heading` 左：`正在生成向量并写入索引` |
| 完成 / 总量 | `.ratel-index-heading` 右：`8 / 97 篇` |
| 比例 | 进度条本身（宽度），不再写文字 |
| 剩余 | **删除** —— 由「已完成 / 总量」可推导 |
| 失败 | 仅 `failed > 0` 时显示；为 0 不出现 |
| 未知总量 | 保留 `totalUnknown`，仅 `total === 0` 时 |
| 阶段须知 | 保留一行，说明当前动作与「已完成可检索」 |

### 版面（方案 A + 局部视觉统一）

```

正在生成向量并写入索引                    8 / 97 篇

正在分批生成向量并写入分片索引；已完成的可检索
────────────────────────────────────────
嵌入模型                            本地 · 就绪
上下文
已用 / 上限          6,647 / 1,048,576 tokens · 估算
▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░
                                  [压缩上下文]
```

**局部视觉统一（C 的轻量部分，不做卡片化）：**

1. 两处进度条共用同一组 CSS 值：高度 4px、圆角 2px、`margin: 6px 0`、同一背景变量；上下文区那条改为与索引区完全相同的类（保留 `role`/`aria-*` 与 `ctxPct` 数据）。
2. 两处 section 标题节奏统一：同一 `padding`/`margin-top`、同一底边框；索引区标题与上下文区标题之间用同一套间距。
3. 数字统一 `font-variant-numeric: tabular-nums`，与索引计数一致。
4. 索引区内部间距收紧：heading → 进度条 → 须知 → 嵌入模型行，共用一个 `gap` 节奏，避免截图里那种几段各自留白。

### 保留不动

- 状态栏 `StatusLine`（「索引中…」）是另一组件，属常驻摘要，本轮不动；
- 底部功能导航、压缩上下文按钮、诊断折叠区、失败/暂停/部分可用须知分支；
- `indexProgressView()` 与所有 counters 口径（只改渲染哪些，不改算哪些）；
- 所有状态色映射、`ratel-progress-unknown` 动画（总量未知时仍需要）。

## 文案（i18n）

| 键 | 变更 |
| --- | --- |
| `status.drawer.indexProgress` / `remainingCount` / `failedCount` | 不再在常态渲染时调用；保留键供其它分支/未来使用，不删除避免破坏既有引用 |
| `status.drawer.totalUnknown` | 保留，`total === 0` 时显示 |
| `status.detail.embeddingWriting` | 保持现有文案 |
| 新增 `status.drawer.indexedCount` | 不变，作为唯一数字表达 |

不新增用户可见字符串；`失败 0 篇` 消失不需要新文案。

- `npx vitest run tests/ui tests/i18n.test.ts`（抽屉快照/文案用例）
- `npx tsc --noEmit -p tsconfig.json`
- `eslint src/ui/status/StatusDrawer.svelte`
- `node esbuild.config.mjs production` → 软链 Sandbox → 重载，人工核对：
  - 索引中只出现一个数字（`8 / 97 篇`）、一条进度条、一行须知；
  - 失败为 0 时不出现「失败」字样；
  - 上下文区进度条与索引区等高、等距；

## 自审

- **占位符**：无 TBD/TODO。
- **一致性**：`progress.completed/total` 仍是唯一数据源；`percentage` 只驱动宽度，不再驱动文字。
- **范围**：仅展示层，无状态语义、无数据存储、无协议改动，单文件可完成。
- **歧义**：「失败仅在 >0 时显示」已明确；「剩余删除」已明确；「两区进度条统一」已明确到具体 CSS 属性。

## 第二轮：层次细化（2026-11-06 目视反馈）

用户确认去重无问题，但反馈「层次有点不清晰」。复核后判断根因不是间距，而是**三种不同性质的内容被排成同样权重**：分组标题、主状态行、辅助说明/属性行都是相近字号与颜色，靠几段留白区分，读起来像一串平铺的行。

补一层明确的三级权重（纯 CSS，不改数据、不改文案）：

| 层级 | 元素 | 处理 |
| --- | --- | --- |
| 1 分组 | `.ratel-drawer-section-title` | 11px / `--text-faint` / 字距 0.4px / `margin-top: 14px` / 细底边 —— 退为分组标签，不与主状态争夺注意力 |
| 2 主状态 | `.ratel-index-state` + `.ratel-index-count` | 13px/600 主状态为唯一强权重；计数降为 11.5px `--text-muted` |
| 3 辅助 | `.ratel-index-notice` + `.ratel-drawer-label` | 说明行加 2px 左侧细线与 8px 缩进，明确「这是主状态的注解」；属性标签用 `--text-faint` |

不引入卡片、背景块或阴影（遵守 `obsidian-ui` 约束）；分组靠间距与细线、从属靠缩进，全部颜色仍走 Obsidian 变量。

验证：`vitest run tests/ui` 425 例通过；`tsc --noEmit` 0 error；`eslint StatusDrawer.svelte` 0 error。待 Sandbox 目视确认。
