# 索引断点续建与文件变更一致性

Spec ID：`S-INDEX-RELIABILITY`  
关联需求：`BUG-1-INDEX-001`，见[索引可靠性需求](../../prd/index-reliability.md)。[Project](https://github.com/users/golddream-y/projects/1) 复用原条目，未创建公开 Issue。  
设计状态：按用户授权由 Agent 自审定稿；已关联 [P-INDEX-RELIABILITY](../plans/2026-10-31-index-reliability.md)（Pending，实施从 T0 可行性验证开始），未启动实现或确定发布版本。设计裁定不再等待用户确认；T0 失败须回到设计修正，不能跳过。

本设计将索引完成单位从「整个知识库的一次请求」改为「一个文件版本的持久提交」。目标是中断后复用已完成工作，同时保证恢复、变更和检索使用同一份版本依据。

## 背景

1.2.1 已阻止超时后的并发清库重试，但仍未支持断点续建。当前 `PersistentIndexBackend` 在修改前删除全库清单和构建戳，仅在整批请求成功返回后重新保存。任一中断都可能使下一次启动走全量重建。

2026-10-30 的后续诊断确认：控制台出现 `Worker request timeout: index.full` 后，磁盘中的向量数量仍增加；实际 `WorkerManager` 的隔离复现也证明，超时后的进度被忽略，迟到完成仅释放写保护，无法返回后端继续提交元数据。整批完成回调不能再承担唯一的持久化职责。

现有进度仅在整篇文件处理后发出。生产实例为何长时间没有收到有效的文件完成进度，尚未确定；后台运行或休眠不是已确认原因。本设计同时补充阶段活动诊断，不将延长超时作为解决方案。

## 目标与非目标

必须保证：

- 每个已持久提交的文件版本独立有效，其他文件失败或程序退出不使它失效。
- 重启重新核对当前文件，只计算新增、变化、不兼容或未完成的内容。
- 文件更新、删除和改名不会留下旧块，也不会把旧快照登记成最新内容。
- 检索只读取完整提交的版本；失败不暴露半成品，不清除无关文件的索引。
- 索引任务可以经历停滞、恢复和重启，状态与实际提交结果一致。
- 内存和待处理队列有界，不为全库预先读取并长期保留所有正文与向量。

不更换 Vectra、不引入原生模块，不扩展到附件索引、聊天持久化或网络通知。不实现单次 ONNX 调用内部的断点续算，不承诺系统休眠期间计算。不操作日常库插件，不因本 spec 自动发布。

## 详细设计

### 1. 文件版本与持久化记录

沿用本地 JSON 和 Vectra，新增可恢复的文件级提交日志，目录约定见本节。逻辑上区分下列记录，不能仅用全库的完成布尔值判断有效性：

| 记录 | 必要信息与职责 |
| --- | --- |
| 索引配置 | schema 版本、嵌入来源及模型身份/可用修订、向量维度、分块器版本、实际生效分块参数及影响嵌入文本的配置，生成 `configFingerprint`；不包含密钥 |
| 已提交文件 | 规范化相对路径、实际输入内容的 hash、配置指纹、提交 ID、块数量及块集合校验信息；mtime/size 只作为辅助信息 |
| 待提交事务 | 事务 ID、操作类型、目标路径、预期输入 hash、配置指纹、旧版本信息及恢复所需的新块数据/引用；仅存本地，不额外复制原始正文 |
| 扫描状态 | 本轮任务 ID、扫描是否结束、待处理/失败数量和失败分类；用于调度与展示，不证明文件已提交 |

文件版本由路径、内容 hash 和配置指纹共同决定。空文件也提交 `chunkCount=0`，否则每次启动都会重复处理。完成进度只计入已持久提交的文件，模型推理结束或向量写入结束都不能提前计为完成。

完成记录采用临时文件写入、必要的 flush 和同目录原子替换；提交日志写入顺序必须可在进程任意一步退出后恢复。不宣称独立写两个 JSON 文件就是跨文件事务。全库清单可以由文件记录重建，构建戳只描述配置，均不再是抹掉全部已完成工作的开关。

新目录结构确定为 `.index/control.json`（schema 与活动代际指针）、`.index/generations/<generationId>/`（`config.json`、Vectra 数据、`files/<pathHash>.json` 完成记录及 `pending/` 事务）。`pathHash` 为规范化相对路径的 SHA-256，记录内保留原路径并校验匹配，禁止用未校验的日志路径访问任意文件。`generationId` 是配置指纹对应的唯一持久标识，不以每次启动时间创建新代际。

路径验证拒绝绝对路径、空路径、NUL、父级越界，以及解析后逃出所属根目录的符号链接；分片名必须是事务目录内的普通文件名，不接受跨目录引用。坏日志能确定归属时只隔离对应路径；无法确定关联文件或代际时，停止该代际的恢复与检索并报告元数据损坏，不猜测归属后继续写入。

`pending/<transactionId>/` 中的向量按批次存放，最终以 `prepared.json` 原子记录全部分片名称、hash、输入 hash、旧提交 ID 和预期块集合。没有 `prepared.json` 的不完整准备数据不具备重放资格，清理后只重算该文件。零块更新与删除也有 prepared 记录，不能依赖「找到新块」判断是否成功。`files/` 记录与 prepared 记录均带版本和校验信息；损坏记录不能作为成功依据。

文件完成记录明确区分 `present` 和 `deleted`：空文件属于 present，仍有正文 hash；删除记录属于 deleted，`inputHash=null`、零块，作为持久删除凭据保留。删除后同路径重新创建按新版本处理，不因旧删除事务重放而删掉新文件。每个路径保存单调递增的 `revision`，prepared 携带预期前驱 revision/commitId；不以时间戳判断先后。

### 2. 单文件更新与崩溃恢复

更新一篇文件的完整流程如下：

1. 读取实际内容快照并计算 hash，捕获本轮配置指纹；分块和嵌入按有界批次处理。
2. 推理完成后再次核对当前内容、文件存在性与配置。输入已过期则丢弃这次未提交结果，并按当前内容重新排队；不提交旧快照为最新版。
3. 先持久保存待提交事务，包含足以重放的新向量及块元数据。事务成功落盘后，才允许替换原索引中的这篇文件。
4. 在 Vectra 的同一个文件事务内删除该路径的全部旧块并写入完整新块。每个新块关联提交 ID；空文件执行完整删除。向量数量、维度和有限值先校验。
5. 向量事务成功落盘后，原子更新该文件的已提交记录，再清理待提交事务。最后报告该文件完成。

此顺序保留旧版本直至新向量准备好，并使「向量已写、完成记录未写」可通过日志重放恢复，无需再次嵌入。清理日志失败不撤销已提交结果；恢复时按事务 ID 校验并幂等清理。若日志写失败，不修改旧向量。若向量写失败，保留旧有效版本或完整新版本及恢复依据，将该文件列为待核验，不假定磁盘一定回滚。

现有 `deleteByPath()` 使用固定 512 维零向量查询前 100 个候选后筛路径，不能用于完整删除。实现必须通过 Vectra 的完整条目枚举，或经验证的完整 metadata 枚举获得该路径的全部 ID；删除与插入放在同一个 `beginUpdate/endUpdate` 中，禁止调用会提前独立提交删除的现有路径。当前 `reembedFile()` 在推理前删除旧块，也必须移除该顺序。

Vectra 的内存回滚不能保证磁盘文件原子性。通过其公开 `FileStorage` 注入项目自己的原子存储适配器：目标文件写入同目录唯一临时文件、flush、rename，成功后再更新内存视图；不修改 node_modules、不依赖 Vectra 私有字段。提交抛错后暂停该存储实例的查询与写入，重新加载并对照 prepared 事务验证磁盘结果，再选择补写记录或重放。不得把「endUpdate 抛错」直接等同于「磁盘仍是旧版」。

提交与查询共用存储协调通道，查询不得读到 Vectra 文件事务的中间状态。提交阶段持有写保护的时间不得覆盖模型推理；推理与持久化通过调度器协调，避免长推理阻塞全部已有索引的查询。

恢复先于对外开放索引。根据待提交事务、已提交记录和实际块集合核对：

| 退出位置 | 下次启动的行为 |
| --- | --- |
| 推理期间，待提交事务尚未保存 | 只重做该未提交文件，其他文件直接复用 |
| 待提交事务已保存，向量尚未提交 | 当前内容/配置仍匹配时重放保存的向量，不再嵌入 |
| 向量已提交，文件记录尚未提交 | 校验提交 ID 与块集合后补写文件记录；不因计数相同就认定有效 |
| 文件记录已提交，日志未清理 | 验证后幂等清理，不再次计算或重复插入 |
| 待提交输入已经过期 | 不将旧事务发布为当前版本；隔离该文件的可疑结果，重新处理当前内容 |
| 日志或向量不可恢复 | 仅使对应文件失效并重新排队；目录级损坏单独报告，不自动清全库 |

过期 prepared 事务必须先核对磁盘：若仍为旧提交，保留旧完整版本；若磁盘已包含过期新提交，该路径暂时不可检索，直至当前版本重新提交；禁止直接删除日志并把已有旧记录当成磁盘真值。恢复重放需要重新持有写所有权并再次核对内容/配置。每次重放均完整替换目标路径，包含零块和删除操作，因此重复执行不会增加块或遗漏旧块。

同路径至多有一个未决 prepared 事务。后继版本开始前先核验前驱并持久登记其已提交或已废止；旧日志只允许在实际前驱与预期相符时重放。若 receipt 已指向更高 revision，旧事务仅校验并清理，绝不覆盖后继版本。日志清理失败可保留已结算日志，但不能让它重新获得提交资格。块集合 hash 必须覆盖有序块 ID、版本元数据及向量值；只检查数量和维度不能证明同一提交。

进程崩溃后的磁盘内容可能早于最后一次界面刷新，因此只有持久提交成功后才递增完成数。整机断电的耐久性取决于底层文件系统；实施必须验证原子替换、flush 和 Vectra 失败行为，不能以 mocks 代替磁盘故障测试。

### 3. 启动扫描与运行时文件变化

启动时先恢复事务，再枚举当前可索引文件并核对已提交记录。枚举、读取、hash 与调度采用有界队列；启动需要一次随文件数增长的核对，不承诺常数时间启动。mtime/size 可辅助调度，但不能单独证明内容未变，必须覆盖时间戳未变化而正文变化的情况。

- 未变化且配置兼容：复用，不调用嵌入模型，不重写对应向量。
- 新增或修改：按最新内容入队。同一路径的事件合并，优先保证其他文件能够继续推进。
- 删除：持久记录删除事务，在存储事务中删除所有块，再写 deleted 完成记录。删除失败时搜索先过滤该路径，恢复后继续清理，不嵌入已删除内容。清单视图不再计入该文件，但不能提前丢掉删除凭据。
- 改名：本轮采用旧路径删除、新路径新增；不承诺跨路径复用向量。旧路径立即过滤，新路径完成后才提供新引用。
- 变空：以零块版本正常提交，移除所有旧内容。

监听器应在首次枚举前装配，扫描结束后再核对期间积累的事件，覆盖枚举与监听之间的空隙。每个路径维护递增的事件序号；文件读取前后与提交前核对序号和内容。变化发生在最终核对之后时，旧提交只能表示旧 hash，后续事件必须保留并重新排队，不能被批次结束清空。连续编辑的热点文件去抖后重试，其他文件不被拖住。

检索结果与「已是最新版」分开：普通修改尚未更新时可使用完整旧版本，但检索工具必须携带过期状态、来源版本，UI 和模型不得称其为当前内容；若消费链路不能表达过期状态，则过滤该结果。已删除、黑名单排除或已确认损坏的内容始终过滤。引用打开当前笔记不代表旧块偏移仍准确，过期结果不得承诺精确块定位。

本轮选择过滤已知过期结果，暂不增加过期引用展示。过滤必须在原始向量候选进入融合、重排和工具返回之前执行，不能先把片段交给模型再过滤最终结果。启动核对按文件逐个解除「尚未核对」标记；扫描未结束不阻止已核实且已提交文件的检索。路径集合与 hash 是轻量索引状态，不把全部正文保留在内存。

### 4. 任务、超时与取消

引入独立于单条请求等待的索引任务生命周期。索引文件提交由持久化协调器负责，不依赖 UI Promise 一直存活；请求超时不能抛弃真实终态的接收和提交路径。

逻辑状态区分扫描、处理中、停滞、暂停、部分失败、失败和就绪。就绪仅在本轮扫描结束、事务已处理、事件队列已收敛且无未处理失败时成立；部分可用通过单独的可检索文件数表达。

- 活动事件包含任务 ID、请求 ID、阶段及单调递增序号。分块批次、嵌入批次完成和实际持久化步骤可报告活动，计时器空转或 Worker 心跳不能冒充工作进展。
- 无有效活动达到阈值时进入停滞，保留任务与写保护，不清库、不并发启动替代写任务。迟到的有效活动可恢复处理中，真实完成仍能提交和更新状态。
- 永久挂起时提供明确的暂停/取消恢复路径。停止调度新文件；可安全终止的嵌入 Worker 由所属端口终止并清理请求。执行中的存储写操作在确认结束前继续占有保护；无法证明停止时明确显示正在停止，不启动冲突操作。
- 卸载时停止调度，不依赖卸载回调完成耗时写入。下次启动依据持久事务恢复；旧实例事件不能更新新实例状态。
- 普通查询等非索引请求保留有界超时；搜索拥塞、模型异常与磁盘错误分别呈现。新设计不得把所有请求都改成无限等待。

后台切换不改变任务状态。系统暂停时不能保证计算，恢复后根据活动及持久状态继续；不得仅凭墙上时间跨度把任务永久判为失败。诊断记录阶段、持续时间、批次及数量，不记录正文、向量、私人路径或密钥，不增加遥测或外发目的地。

写所有权作用于整个索引根目录，覆盖旧代际、待建代际、迁移和清理。同一 renderer 的插件重载通过 `globalThis` 上按规范化根目录登记的共享协调器交接：旧实例先撤销调度 epoch，禁止迟到推理开始新提交，已进入的磁盘提交由共享协调器继续完成或保留恢复日志；新实例等待 closing Promise 后才创建存储实例。

不同进程通过索引根下排他创建的 owner 锁拒绝第二写入者，锁记录实例令牌、进程身份和 schema。休眠、心跳停止或租期过期都不能证明旧写入者死亡，不得据此抢锁。只有能确认旧 owner 已退出才恢复；身份无法核实时报告占用并拒绝写入，不能删除锁强行继续。本轮不支持多个进程同时写同一索引。

锁至少区分本机进程身份、renderer 实例令牌与协调器版本。其他机器同步来的锁、无权限检查的进程、PID 仍存活但实例身份不明均拒绝自动回收。本机确认进程不存在时，回收方先排他取得恢复锁，在锁内重新读取 owner 并核对原令牌；所有 owner 创建/释放也服从该恢复门，禁止两个回收方依据同一旧快照先后删除新锁。恢复门自身不按过期时间抢占；无法证明其持有者结束时保守报占用。T0/T2 必须测试双进程同时恢复与令牌被替换的情况。

暂停/取消先撤销调度 epoch，再中止可中止的模型调用并等待活动提交收尾；取消不删除已提交记录或 prepared 事务。嵌入 Worker 若为查询与索引共享，不能为取消一项任务直接终止所有使用者；优先在批次边界停止，永久挂起需要明确进行整个嵌入运行时重置，并令其他受影响调用按真实失败结束。恢复动作创建新 epoch，旧回调的结果不得进入提交。

### 5. 配置变化与旧索引迁移

兼容性以实际生效配置判断，切换对话模型但未改变嵌入/分块配置，不触发向量重建。无法区分相同模型名称背后的修订时，保留显式重建入口，并说明这一识别限制。

旧有效清单与构建戳：验证 schema、配置和每篇文件的实际块集合后，导入文件完成记录；当前内容未变化的文件不重新嵌入。旧版全量清单中的块数可能为零，不能直接当作空文件，应检查实际存储。

旧半成品缺少可信记录：保留为不可直接采用的旧数据，不将「路径存在、块数非零」作为内容正确的证据。仅在能验证输入 hash、配置和完整块集合时复用；否则需要一次受控重算，界面明确说明原因。重算从首个文件开始按新规则保存检查点，后续中断不再重算已提交文件。不承诺无依据挽救全部旧计算。

配置不兼容时在隔离的新配置代际中逐文件构建，不混用不同维度或配置的向量，也不先删除旧有效代际。新代际完成后原子切换活动指针，清理旧代际失败不得破坏新索引。构建期间旧代际只有在对应嵌入配置仍可调用时提供明确的旧配置搜索，否则显示暂不可用。切回相同配置时验证并复用该代际的检查点；限制保留代际及暂存数据，避免无限增长。

首次建库没有旧活动代际时，在首个文件持久提交后原子登记该代际为活动代际，仅开放已核对完成的文件，不等待全库完成。配置切换则保留旧活动指针，新代际需完成扫描、队列收敛和全部文件提交后才切换；部分失败不能切换。切回旧配置时按指纹查找代际，先恢复/核对，再复用；不为同一配置反复创建空目录。默认保留活动代际和一个待建/回退代际；需要第三个时只回收不活动、不在提交且无未解决事务的代际，否则暂停创建并报告占用。

旧版清单缺少单块内容 hash，验证仅有总块数不够。迁移必须以清单记录的输入 hash 对照当前内容，再用当前兼容的分块器生成预期块集合，完整检查块 ID/序号、边界与结构元数据、维度、有限值和多余块。可确认兼容的有效旧索引允许采用其成功清单作为模型输出来源证据；缺失字段、块集合不匹配或配置身份不能确认的文件单独重算，不能重算其他已验证文件。

迁移在 owner 锁内只读复制旧 Vectra 数据及其引用的外置 metadata 到独立的代际目录，核对复制摘要后生成文件完成记录，最后发布 control；不先移动/清空旧数据，不在旧根目录上直接启动新方案的可写存储。复制中断可重入，完整复制不重复嵌入，但可能产生一次等规模本地 IO 和空间开销。旧 `.index/` 根目录包含 control、owner 及新代际，绝不作为代际回收目标；legacy 清理仅删除已核验的旧 Vectra 文件白名单，不递归删除根目录或未知文件。

`autoIndex=false` 下不做内容新鲜度承诺：仅只读采用可信已提交记录，未解决事务路径全部过滤，明确标记未扫描；不声称已核对当前 Vault。每次检索只核验候选文件的存在性与当前黑名单，不扫描全库；无法核验的候选过滤。若无可信记录则保持不可检索，不为显示 ready 而偷偷恢复写入。

旧配置没有端点身份和修订信息时，只能迁移身份可以重建的本地已知模型；API 同名模型无法证明仍属同一端点/模型空间时，按不兼容处理。不得根据当前设置补造旧配置的端点指纹。

`autoIndex=false` 保持只读契约：不自动读取全库、恢复写事务或调用模型，只开放可验证的已提交部分，并过滤尚未解决的事务路径；需要恢复的状态明确显示，待用户启用索引或显式操作。黑名单变化立即收回搜索与模型可见性；自动索引关闭时仅排队清理，待用户启用索引或明确执行清理操作后才修改本地派生数据。

### 6. 规模与存储成本

保留有界文件处理和嵌入批次，不一次构造全库正文数组。待提交向量仅保留活动提交所需的数据；成功后及时回收。事件队列按路径合并，不随每次键入无限增长。

现有 Vectra JSON 持久化可能随索引规模增加写放大，按文件检查点本身不能解决这一成本。实施前必须在临时目录验证现有事务与磁盘行为；若不能实现上述文件替换和恢复契约，停止该实施路线并修订 spec，不通过先删除旧内容降级保证，也不擅自换数据库。

基准覆盖小库与数千篇合成笔记，记录总块数、总耗时、嵌入调用数、重启恢复耗时、峰值内存、磁盘写入量和主线程长任务。至少包含大量短文件和单个大文件两种分布。plan 定义相对现有成功路径的性能门槛，T0 采集基线、T8 复测；这些是设计验收目标，不是已有实测或启动秒数承诺。

向量推理按批次写入事务暂存分片，全部批次准备好后才进入文件替换；一次文件提交不可降级为逐批对外可见。内存上限包含 Vectra 必需的活动索引视图以及一个活动推理/提交文件，不承诺向量索引本身常量内存。大文件的分块器与 Vectra 序列化仍可能产生主线程长任务，需在基准记录并作为交付风险处理，不能把 InlineWorker 当成真实后台线程。

## 影响面

主要涉及 `PersistentIndexBackend`、`IndexManifest` 与构建戳、`IndexManager`、Vectra 适配器、`IndexProcessor`、Worker 请求与嵌入协议两端，以及反馈状态、检索消费和国际化。`main.ts` 只做装配，不增加持久化或恢复算法。

需同步索引/Worker 架构说明、用户指南和发布时的 CHANGELOG；本稿不提前修改现役架构文档。保持 Obsidian API 外观边界，Embedding Web Worker 不引入 Node、HTTP 或宿主 API。实现前检查索引数据 schema、存储原子性与协议兼容，不能只更新发送端。

## 验收标准

以下为待实施验收，尚未运行。所有自动化故障注入使用临时磁盘；图形验证只使用 Sandbox。

| 编号 | 验收场景 | 必须观察到的结果 |
| --- | --- | --- |
| A1 | 首次索引提交若干文件后终止进程，重新构造全部实例 | 已提交且未变文件嵌入调用数为零；只处理未提交文件 |
| A2 | 向量提交前后、文件记录保存前后分别中断 | 从真实磁盘日志恢复；匹配输入的已暂存向量不再次计算；无半文件或重复块 |
| A3 | 重启期间新增、修改、删除、改名；正文改变但保留 mtime/size | 结果与当前文件一致，无旧路径、残留块或误复用 |
| A4 | 推理期间修改/删除文件，提交期间再次修改，连续编辑同一路径 | 旧快照不标记为最新版；队列最终收敛，其他文件继续推进 |
| A5 | 文件变短、变空和单文件失败 | 旧多余块清除；空文件可复用；其他成功文件不因本文件失败失效 |
| A6 | 日志、向量、文件记录或清理各阶段注入 IO 错误 | 失败范围可定位；可恢复重试；不清全库、不假完成、不暴露半成品 |
| A7 | 模拟停滞、迟到活动及迟到成功，后台暂停/恢复，重复旧事件 | 状态能恢复并真实提交；无重叠写、错误归属或永久丢弃完成路径 |
| A8 | 永久挂起、取消、卸载和重启 | 等待有明确状态；安全停止前不开放冲突写；已提交检查点仍可复用 |
| A9 | 有效 1.2.1 索引与缺元数据半成品分别迁移 | 前者验证后零重复嵌入；后者不冒用有效性，受控重算也可续建 |
| A10 | 更换嵌入/分块配置、中途退出、切回原配置 | 不混向量代际；旧有效数据保留；兼容检查点可复用 |
| A11 | 搜索与更新并发、过期结果、删除/黑名单、自动索引关闭 | 仅消费完整且允许使用的版本；过期明确标识或过滤；关闭后零自动扫描/嵌入/修写 |
| A12 | 数千篇合成文件、多次中断恢复和再次无变化启动 | 已提交版本无重复嵌入；有界队列与内存证据；记录写放大与交互影响 |

持久化正确性需真实临时磁盘与进程重建测试；超时与事件竞态使用可控时钟。单纯模拟成功回调或只验证正常退出，不满足断点续建验收。
