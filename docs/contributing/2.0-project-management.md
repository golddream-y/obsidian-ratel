# 2.0 Project 字段与视图方案

> 2026-10-20 · 从路线迁出的管理建议，尚未应用到远端；本次只调整文档归属，不批准字段与视图变更。

操作规则、确认节点与生命周期同步以[项目管理 Skill](../../.agents/skills/ratel-project-management/SKILL.md)为准。本页保留本项目尚待确认的字段与视图方案，不另维护一套执行流程。

## 1. 字段与视图建议

继续使用[同一个 Project](https://github.com/users/golddream-y/projects/1)，按条目层级和规划窗口查看演进。下列字段与视图为待审方案，尚未应用到远端。

### 条目层级与信息归属

| 层级 | 跟踪对象 | 推进原则 |
|---|---|---|
| 产品目标 | 现有一张 2.0 目标卡 | 维护总体目标，不因局部上线判定完成 |
| 方向需求 | 现有五张方向需求卡 | 保留长期入口，关联跨阶段能力 |
| 交付特性 | 可独立验收的用户结果，如材料可检索查看、来源可核查 | 范围明确后建立；跨方向贡献引用需求，不重复建卡 |
| 执行任务 | 确有独立跟踪需要的实施工作 | 不为每个工具、文件或测试单独建卡 |

| 信息 | 维护位置 | 更新时机 |
|---|---|---|
| 产品目标、功能范围与验收 | [整体 PRD](../prd/2.0/README.md) | 产品需求变化或范围确认 |
| 阶段目标、依赖与通过条件 | [演进路线](../roadmap/2.0.md) | 演进顺序或阶段边界变化 |
| 当前选择、优先级、待确认事项与实际进度 | Project | 协作节点与近期取舍变化 |
| 技术设计与实施步骤 | spec / plan | 对应范围与文档确认后 |
| 版本范围与实际交付 | Milestone / Release / CHANGELOG | 版本范围确认及发布 |

### 推荐字段与状态语义

| 字段 | 建议值 | 使用说明 |
|---|---|---|
| 条目层级 | 目标、方向需求、交付特性 | 执行任务按需要增加 |
| 规划窗口 | 未安排、当前、下一步、后续 | 表示关注顺序，不承诺发布日期 |
| 需求阶段 | 待澄清、待需求确认、已确认、暂缓、取消 | 表达范围是否明确及是否继续 |
| 工作阶段 | 未开始、待文档确认、设计中、待设计确认、实现中、验证中、待发布、已交付 | 表达工作实际推进位置 |
| 原生 Status | 保留 Todo / In Progress / Done | 供粗粒度查看，不替代上述两种阶段 |

| 状态判断 | 处理规则 |
|---|---|
| 新增字段 | 核对迁移草稿中的已有记录，不自动推进状态 |
| 方向卡有局部交付 | 不直接套用子特性完成状态 |
| 暂缓或取消 | 保留真实原因，不冒充成功交付 |
| 已合并、未交付 | 标为待发布 |
| 已有试用交付 | 记录试用证据，不等同稳定版发布 |
| 日期、负责人、精细优先级 | 有实际需要时补充，不先制造排期 |

### 推荐视图

| 视图 | 条目与组织方式 | 主要用途 |
|---|---|---|
| 2.0 方向总览 | 目标与方向需求 | 查看整体范围和 PRD |
| 能力演进 | 交付特性按当前、下一步、后续分组；保留未安排入口 | 查看近期取舍与能力依赖 |
| 待确认 | 待需求确认、待文档确认、待设计确认条目 | 找到具体确认对象 |
| 开发与验证 | 实现中、验证中、待发布的特性 | 查看 spec、PR 与验证证据 |
| 日期型 Roadmap（按需） | 已有可靠日期或迭代计划的条目 | 有排期依据后再展示时间轴 |

各视图使用同一批条目，不复制卡片。没有可靠日期时先使用表格或看板。

## 2. 方案确认与执行边界

字段与视图确认后，按 Skill 读取远端最新结构再执行，不能因本页写出方案就认为已经配置。需求确认、文档确认、设计、实现、发布和归档分别依其真实节点同步；不改变现有 Todo / In Progress / Done 语义。
