# 支柱 C — 生态管理

> 产品总纲入口：[overview.md](overview.md)。

架构正文：[执行层](../architecture/host/ecosystem.md)、[档案层](../architecture/host/plugin-profile.md)。

Ratel 的管理对象从知识库扩展到工作环境。需求按用户能感知的阶段写，不按 schema 字段写。

| 域 | 对象 | Agent 能力 |
|---|---|---|
| Ratel 自身 | 本插件设置、密钥、技能 | 读配置、白名单内代改、密钥只看状态、定位设置页（已有能力） |
| Obsidian 官方 | 核心设置（外观、快捷键、核心插件） | 只引导：定位到对应设置页并文字指路，不代改 |
| 社区生态 | 其他社区插件 | 对话里寻找、安装、升级、卸载、按需配置、回滚 |

**宿主没有官方「插件管理」权限。** 公开 Plugin API 不提供 install/uninstall；Ratel 不能向 Obsidian 申请这类授权。桌面端（本插件已是 desktop-only）在用户确认后，可写当前库的插件目录与启用清单，并尽力调用未文档化的运行时启用接口。热启用失败时必须说明，并引导重载或到官方社区插件页操作，不得假装已经启用。不装商店清单外的来源；不管理 Ratel 自己的目录。社区商店上架本能力前须过审核口径（先例有 BRAT 等，不保证过审）。

阶段关系：

```
1 配置规范 → 2 创建配置 skill
                  ↓
3 对话寻找 / 安装 / 升级 / 卸载 → 4 对话配置
                  ↓
              5 变更可回滚
```

**阶段 1 — 配置规范**

全库一份插件配置档案格式（不是每个插件一套 schema）。规定档案必须绑定商店 `pluginId`、点名可写 key、禁忌 key（密钥等永不代写）、场景 preset。详见 [S-PLUGIN-PROFILE](../superpowers/specs/2026-09-10-plugin-profile-design.md)。

**阶段 2 — 创建配置 skill（档案）**

按规范手写，或从已装插件识别生成草稿。草稿默认不生效、不拿去改别人的设置；人启用后才能进入匹配。第一期只要求规范 + 识别草稿 + 一份示例档案，不要求热门插件全集。

**阶段 3 — 对话寻找、安装、升级、卸载**

入口是对话，不复制官方商店界面。

- **寻找：** 用户用自然语言描述需求；只在官方社区清单内检索；结果含作者、下载量、说明、是否已装；整份清单不进模型上下文。
- **安装：** 确认弹窗后下载该插件官方 GitHub release 三件套，写入 `.obsidian/plugins/<id>/`，写入启用清单，并尝试运行时启用。
- **升级：** 覆盖三件套，**保留** 该插件 `data.json`。
- **卸载：** 先备份再移除目录并禁用。

每次装/升/卸都要人点头。下载中断须清理半成品。启用失败须回滚或明确残留与下一步，不留「装了但不可用」却不说明的状态。

**阶段 4 — 对话配置**

- 有匹配档案：展示将改的 key 与前后值，确认后按最小 diff 写入（展开仍是点名 key）。
- 无档案：读取 `data.json`，解释结构，点名修改；未知 key 先确认，不整文件重写、不猜测。
- 密钥类只引导打开该插件设置页，不代填。
- 写入后对方插件未必立刻热更新设置；允许提示重载。禁止用 Skill 脚本写他人 `data.json`。

**阶段 5 — 变更可回滚**

每次环境变更（安装、升级、卸载、启用清单、配置 key）追加 `EcosystemChange`：动作、目标、前后摘要、备份位置。日志在本地插件目录，append-only。「撤销刚才的改动」是一等能力。

**安全边界**

- 路径白名单在 adapter 层：仅清单校验过的 `plugins/<id>/` 与 `community-plugins.json`；Ratel 自身目录与 Obsidian 核心配置不可达。
- 只装商店清单内插件；确认弹窗展示作者与下载量。
- 清单与 release 出站须 ADR-018，README 隐私说明同步。


## 关键用户流程

1. （可选）作者按规范创建配置档案，或从已装插件生成草稿并启用。
2. 用户用对话描述需求（如「我想要看板」）。Agent 在官方社区清单内推荐，展示作者与下载量。
3. 用户确认后：备份 → 下载商店三件套 → 写入插件目录 → 尝试启用。热启用失败则说明并引导重载或官方页，不假装已启用。
4. 升级只换插件本体，保留用户配置；卸载先备份再删。
5. 需要配置时：有档案则预览 preset 再最小 diff；无档案则点名 key。密钥不代填。
6. 反悔时从变更日志回滚到变更前。

## 生态管理安全

- 网络出站仅发生在用户发起生态操作时（GitHub 清单获取与 release 下载）；清单本地缓存，默认 7 天；
- 路径白名单为 adapter 层物理校验，不依赖模型自觉或 prompt 约束；
- 恶意插件防线：只装商店清单内插件、确认弹窗展示作者与下载量、最终决定权在用户；
- 所有环境变更先备份后执行；备份与变更日志存本地插件目录，不进 vault、不出网。
- 产品与文档不得声称 Obsidian 官方授权本插件安装其他插件；公开 API 无 install。热启用依赖未文档接口，失败必须降级说明。
- 本能力仅桌面；社区商店上架前须过审核口径。
