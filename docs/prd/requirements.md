# 功能需求清单

> 产品总纲入口：[overview.md](overview.md)。

| ID | 需求 | 验收口径 |
|---|---|---|
| PI-01 | Heartbeat 支持周期、事件、冷却、安静时段和去重 | 同一规则同一周期不产生重复有效洞察 |
| PI-02 | 从记忆解析日记/月目标等工作约定 | 可追溯约定来源，冲突时不静默猜测 |
| PI-03 | 缺失约定只询问一次 | “没有”被记录后不再主动询问，直至用户更新 |
| PI-04 | 生成昨日简报和条件式今日建议 | 每个结论有来源或明确标注证据不足 |
| PI-05 | 所有主动结果进入统一收件箱 | 支持接受、稍后、忽略、追问与状态同步 |
| PI-06 | 支持 Obsidian 分级投递 | 状态栏、收件箱与 Notice 状态一致且不重复弹出 |
| KM-01 | 融合检索支持语义、关键词与结构信号 | 稀疏链接库仍可用，有图时获得增益 |
| KM-02 | 回答、治理与挖掘保留来源 | 来源在 Obsidian 中可点击定位 |
| KM-03 | 提供知识熵候选检测 | 候选含信号、置信度、来源与建议动作 |
| KM-04 | 提供跨笔记知识挖掘 | 输出主题、关系、缺口/冲突与带来源综述 |
| NT-01 | 状态栏提供稳定的洞察入口 | 未处理数量准确，点击可打开收件箱 |
| NT-02 | 高价值洞察可触发一次 Notice | 重载、重试和恢复不会重复弹出同一洞察 |
| NT-03 | Notice 可导航到完整洞察 | 摘要不截断关键状态，详情保留来源和操作 |
| NT-04 | 支持安静时段、每日上限和按规则关闭 | 用户可控制频率，低价值洞察只入收件箱 |
| TR-01 | 黑名单全链路生效 | 排除内容在索引、模型、MCP、日志和通知中均为零出现 |
| TR-02 | 证据最小披露可审计 | 用户可查看来源和披露目的地 |
| TR-03 | 主动洞察不得绕过写入权限 | 未经用户接受和 Write Gate 时 Vault 零修改 |
| TR-04 | 模型与 MCP 密钥进入钥匙串 | 受版本控制文件和 `data.json` 无明文密钥 |
| PL-01 | Skill/MCP/Subagent 继承会话边界 | 不存在绕过黑名单和审批的执行路径 |
| CFG-01 | 内置「应用配置」Skill:模型可自助引导用户完成 Ratel 自身配置(模型/密钥/索引/诊断) | 用户用自然语言描述配置问题,模型能定位到对应设置项并给出步骤,无需翻文档 |
| CFG-02 | 提供 open_note 工具:模型可在 Obsidian 中为用户打开并定位笔记 | 对话中用户说「打开这篇」时笔记在编辑器中打开并可滚动定位 |
| SR-01 | 从被纠正会话提炼教训候选,经洞察收件箱审阅后写入记忆 | 教训可读可编辑可删除且标注来源;被接受的偏好教训不再重犯 |
| SR-02 | 记忆与 Skill 分层注入:核心约定恒注入,其余按查询相关性取 top-K | 核心约定不因检索排序丢失;Skill 数量增长不线性放大注入体积 |
| SR-03 | Skill 与教训显示注入/使用统计 | 管理面板可见次数;无自动退役行为 |
| EC-01 | 自然语言探索社区插件清单 | 推荐结果含作者、下载量、功能说明与已装标注 |
| EC-02 | 确认流安装商店插件 | 确认后完成下载与写入启用清单；尽力运行时启用，失败则说明并引导重载/官方页 |
| EC-03 | 更新插件保留用户配置 | 更新后目标插件 data.json 内容不变 |
| EC-04 | 卸载先备份后移除 | 卸载后可从备份完整恢复 |
| EC-05 | 点名 key 修改其他插件配置 | 修改前展示前后值,仅目标 key 变化 |
| EC-06 | 生态变更 append-only 日志 | 每次变更含动作、目标、前后摘要、备份位置;用户可查看全部历史 |
| EC-07 | 任意变更可回滚 | 插件目录与启用清单均能恢复到变更前状态 |
| EC-08 | 路径白名单物理校验 | 可写：清单内插件目录、community-plugins.json、点名宿主配置文件；Ratel 自身目录、app.json、外观、快捷键、主题不可达 |
| EC-09 | 点名宿主设置可代改 | 只写白名单上的核心/本机字段；不因「不在 data.json」拒绝。日记根在首次确认时由用户决定，并创建该文件夹。外观、快捷键、app.json、密钥仍只引导 |
| EC-10 | 不冒充官方插件管理授权 | 文档与 UI 不声称官方授权；desktop-only；未文档启用失败有降级；商店上架前过审核口径 |
| PP-01 | 唯一 Profile schema | 全库一份格式契约；插件变多只增加档案实例，不增加 schema |
| PP-02 | 档案绑定商店 pluginId | 对不上 community-plugins.json 则档案作废，不能据此安装 |
| PP-03 | 按规则产出档案 | 写作规则使人或模型产出能通过 schema 的档案 |
| PP-04 | 识别草稿不生效 | 从已装插件生成的草稿默认不匹配、不写入，需人启用 |
| PP-05 | 按意图或 pluginId 匹配 | 用户自然语言或插件 id 能命中档案与 preset |
| PP-06 | 消费时按需安装 | 未装则仅商店清单内确认安装（复用 EC-02） |
| PP-07 | 消费时按需设置 | 只应用选中 preset 或 key 子集；最小 diff、确认、可回滚（复用 EC-05～07） |
| PP-08 | 禁止脚本写他人配置 | 不得用 skill 脚本写目标插件 data.json |
| PP-09 | 底座先交闭环而非插件全集 | schema + 规则 + 识别草稿 + 恰好一份示例档案 |
