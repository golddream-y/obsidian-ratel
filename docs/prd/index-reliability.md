关联需求：`BUG-1-INDEX-001`。在 [Project](https://github.com/users/golddream-y/projects/1) 复用原索引问题条目，未创建公开 Issue。用户于 2026-10-31 确认按文件续建和变更处理方向，并明确要求编写 spec；本次不启动实现或发布。

用户随后将技术设计审查交由 Agent 自行裁定，不再等待用户设计确认；实现前的存储实验门槛和发布授权仍分别保留。

## 问题与预期结果

知识库首次索引可能跨越多次启动。当前完成凭据依赖整批成功返回，中断或超时会导致已有工作不能复用，文件越多重复计算越昂贵。索引期间笔记仍会新增、修改和删除，恢复时必须与当前内容核对。

预期是已成功保存的文件可独立复用，启动只处理未完成或发生变化的文件。索引可以在后台推进；系统休眠时暂停，恢复后继续或安全重试未完成部分。无法继续时明确说明状态，不能把停滞、部分完成或失败显示为全库完成。

## 范围与验收

| 场景 | 预期结果 |
| --- | --- |
| 首次索引中途退出后重开 | 已持久提交且未变化的文件不再次嵌入，只处理未完成文件 |
| 停机期间新增、修改、删除文件 | 启动核对后更新对应文件；删除内容不再被搜索返回 |
| 索引期间修改同一文件 | 旧快照不登记为最新版，最终处理最新内容 |
| 文件变短、变空、改名 | 无残留块、重复结果或旧路径引用；空文件也有完成记录 |
| 某文件处理失败 | 保留其他文件的完成记录，可重试失败文件；全库状态不冒充完成 |
| 更新失败或进程意外结束 | 不向搜索暴露半篇新内容；恢复后能辨认并处理未完成提交 |
| 请求停滞后恢复 | 同一任务恢复显示进度，真实成功后可以保存；不并发清库重试 |
| 模型或分块配置变化 | 识别不兼容范围并建立新索引，不混用不同配置的向量 |
| 自动索引关闭 | 不自动扫描、嵌入或修写索引；明确展示已有索引的新旧状态 |

## 边界

本轮针对现有 Markdown 索引，不扩展格式、通知渠道或云端服务，不更换向量数据库。不承诺一次模型调用内部的逐 token 续算；中断时尚未持久提交的计算可能需要重做。现有缺失可信完成记录的旧半成品不能直接视为有效，新方案必须交代迁移代价。

技术设计与故障验收见 [S-INDEX-RELIABILITY](../superpowers/specs/2026-10-31-index-reliability.md)。现有功能的真实交付情况仍以 Release 为准。
