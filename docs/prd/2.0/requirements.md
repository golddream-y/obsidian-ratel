# 需求草案

> v0.1：总体方向已确认；本页需求细目、验收条件与边界是待审阅候选，不代表进入 2.0.0 的发布承诺。正式 Issue 尚未创建。

需求按完整用户结果组织，暂不拆为实现任务。以下五个 ID 与 [Project](https://github.com/users/golddream-y/projects/1) 的同名私有草稿对应；四条知识主线可以共用基础能力，“办公材料工作区”是贯穿主线的场景，不是第五个知识处理阶段。

| ID | 用户结果 |
|---|---|
| [REQ-2-KS-001](#req-2-ks-001) | 将资料、经验和讨论结论沉淀为可复用知识 |
| [REQ-2-KC-001](#req-2-kc-001) | 根据当前任务使用正确且可核查的知识 |
| [REQ-2-KP-001](#req-2-kp-001) | 人与 AI 逐步形成可检查、可交付的成果 |
| [REQ-2-KE-001](#req-2-ke-001) | 知识和成果随新证据持续修订，保留历史依据 |
| [REQ-2-WS-001](#req-2-ws-001) | 在 Obsidian 中建立能共同使用办公材料的工作场景 |

## REQ-2-KS-001

**知识加工与沉淀。** 用户需要把材料与经验中的可复用部分留下，而不是每次重新解释背景或保存整段聊天。

预期结果：能够从资料或讨论中提出结论、经验、决策和约束候选，说明来源、确认状态、适用范围及未决问题。用户可以调整或拒绝候选；已确认内容与临时猜测、反例及被替代结论可区分，保留关键取舍的理由。

候选验收：在一个包含事实、假设和方案取舍的样本任务中，用户能检查并修正确认结果；下一次相关任务能使用已确认结论，且不把已否定方案当成当前决定；保留原始依据而不要求全文复制。

待确认：哪些内容必须人工确认，如何表达适用范围，用户愿意接受多少整理操作，以及哪些任务不需要正式沉淀。存储位置、标记格式和自动提取方式尚未决定。

## REQ-2-KC-001

**按任务消费知识。** 用户需要让 AI 理解当前目标并找到必要依据，减少无关材料、旧版本和错误约束造成的偏差。

预期结果：结合目标和范围，从允许使用的材料、有效结论及工作约定中选择上下文；区分依据、约束、参考和待确认内容。用户能核查来源、原材料版本、知识结论的有效/历史状态及可用的位置，并看见冲突、遗漏和未覆盖内容。文件更新与结论被替代是两类变化，不能只用一个“最新”标记混同。支持从笔记及其明确引用关系继续找到材料，不将模型推测的关系冒充已存在的链接。

候选验收：对预先标明正确来源、过期材料和冲突信息的任务，能找到相关依据并说明不确定性；同一主题换一个任务目标后能调整使用范围；搜索无命中时说明实际覆盖，不能据此断言所有文件都不存在相关内容。

待确认：任务范围由用户如何表达，哪些信息需要展示给用户，首期定位到什么粒度，以及冲突无法消解时应如何继续工作。

## REQ-2-KP-001

**人与 AI 协同生产成果。** 用户需要从模糊问题走向可用交付，过程中能够判断方向并定位偏差。

预期结果：按任务需要支持目标澄清、观点组织、方案比较、表达与成果制作、检查和修订；保留阶段确认、关键选择及依据。阶段数量和输出媒介由任务决定，不要求每次都走固定长流程。成果能够继续修改，并区分引用事实与新增判断。

候选验收：在一个代表性研究、培训或项目任务中，用户能确认阶段结果；出现问题时能回到相关目标、结构或依据调整，后续工作使用修订后的有效内容；成果按该任务的明确标准检查，而非只凭模型自评“已完成”。

待确认：第一种交付物、需要的阶段控制、验收方式，以及哪些制作能力由现有插件、外部软件或其他工具承担。自动生成或编辑所有 Office 格式不作为本期既定需求。

## REQ-2-KE-001

**知识有效性与持续演进。** 用户需要在资料更新、实践反馈或决策变化后，知道哪些知识还有效，哪些可能需要修订。

预期结果：区分当前内容和历史内容，呈现变更来源及关键理由，提示可能受影响的结论或成果。用户可以选择修订、保留、替代或归档；任务中确认的新结论与反馈能回到长期知识中，后续使用不会静默继续采用已失效内容。

候选验收：更新一个来源或撤销一个结论后，下次相关任务能识别新旧差异；影响提示有依据，无法确定的关系明确标为可能；历史依据仍可查，用户拒绝的修订不会被自动当成事实。

待确认：自动检测与人工触发的边界、过期与冲突的判断责任、历史保留方式、提示频率和批量治理的确认范围。不预先要求后台定时任务或完整版本控制系统。

## REQ-2-WS-001

**办公材料工作区。** 用户把笔记与 Excel、PPT、Word、PDF 等材料放入 Obsidian，希望能够在同一项目工作过程中使用它们，减少插件选择与配置负担。

预期结果：用户知道文件能否查看、内容是否可搜索、AI 实际能读取什么、来源能否定位，以及修改后内容是否仍然有效。场景配置是待选能力：允许按需建立可复用工作场景，协调合适的插件、目录与操作方法，保留原件和既有配置；具体插件组合与配置操作尚未批准。Skill 是方法复用机制；预览器能展示文件不等于 Agent 已获得其内容。

候选验收：用一组笔记与办公文件完成“找依据并核查来源”的任务，明确每种材料的实际覆盖；大文件、纯图片文档、失败或不支持文件不会被静默忽略；修改、移动与删除后的检索结果能反映实际状态。场景启用前解释变更，启用后能检查结果与恢复已支持的配置变更。

待确认：首先覆盖哪些格式，图片内容是否处理，文件管理动作是否包含移动/复制/重命名，以及是否需要生产或修改办公成果。文字提取再检索已作为可行方向讨论，但具体缓存、索引和模型方案不在此批准；文件管理也不默认意味着自动清理或删除重复文件。

## 共同质量要求

安全与隐私：用户能控制材料范围和外发边界；候选验收包括识别此次使用的材料范围、接收内容的模型或工具及目的，并能排除不允许使用的材料。文档内嵌指令不能获得系统指令效力；确认知识结论不等于授权文件修改。原件、派生内容和模型输出之间的关系清楚，不能把本地存储宣传为完全离线或全文加密。

可信与可恢复：显示内容覆盖、过期、失败和待处理情况，区分已核查与待验证；变更失败或中断后说明已有结果与未完成部分，按实际能力提供恢复路径，不笼统承诺任何文件修改都能回滚。

规模与成本：大量文件、几十兆材料和持续修改不能使日常编辑失去响应；用户知道处理进度、资源或远端费用边界，并能控制任务。候选验收包括区分本地处理和远端调用、显示可获得的用量或费用信息，无法估价时明确未知而不是显示零成本。具体容量、延迟、内存与质量门槛要从首期场景和样本得出，不能用嵌入模型体积或文件 MB 数直接承诺效果。

配置与开放性：用户可继续选择模型与工具，场景按实际需要配置，不强装所有格式插件；保持现有可用工作方式，必要迁移必须有说明和验证。图谱、向量、OCR、Skill 或 MCP 都是候选手段，不作为需求验收本身。
