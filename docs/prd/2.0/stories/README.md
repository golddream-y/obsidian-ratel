## 2. 用户故事清单


### 材料接入、查看与基础检索

| ID | 用户故事 | 主要承载 | 完成条件 |
|---|---|---|---|
| US-2-001 | 我能指定材料范围，并知道哪些内容已经可用 | 工程代码与工具 | 能指定与调整选定、排除范围；分别说明正文读取、原词与语义检索、原件查看的实际可用能力，以及覆盖盲区、处理失败和超限原因；部分完成先用，无命中时说明实际覆盖；范围收回行为见共同验收约定 |
| US-2-002 | 我能让 Agent 读取文本型 PDF 的指定内容并核查页码 | 工程代码与工具 | 代表 PDF 的文字可读、可索引；按需读取而非整件灌入上下文，结果可核查到原件页；扫描页明确提示盲区 |
| US-2-003 | 我能让 Agent 阅读 PPTX 的幻灯片文字并找到出处 | 工程代码与工具 | 保留幻灯片顺序与位置；说明备注、图片和图表是否覆盖；命中可核查到正确幻灯片 |
| US-2-004 | 我能在笔记和办公材料里用原词找内容 | 工程代码与检索工具 | 同一范围内对 Markdown 和已提取材料执行原词查找，返回实际命中、上下文和来源；用已知出现位置核对原词召回，并验证提取断行等情况下约定的匹配边界；不把派生文本当另一份原件 |
| US-2-005 | 我记不清原词，也能用含义找到材料 | 工程代码与索引、语义检索工具 | 用含义查询召回人工标注的正确依据，提供必要上下文及与原词查找一致的来源；按检索分册的样本与方法验收质量；语义索引待完成或失败时仍可使用已就绪的读取和原词查找；不对二进制直接向量化 |
| US-2-006 | 我能让 Ratel 准备预览环境，并查看命中的原件 | 内置场景 Skill＋插件工具＋格式预览插件 | 分别验收环境准备与日常查看：准备时优先复用已有能力，按授权补齐缺失插件；日常从结果打开原件无需重新运行安装流程；逐格式验证能否打开及定位，不能精确跳转时提供可核查位置与降级 |
| US-2-007 | 我修改、移动或删除文件后，不会被旧结果误导 | 工程代码与索引工具 | 变更后标明待更新或失效，旧结果不得冒充当前内容；更新期间若提供旧内容须标注原件已变化；重命名/移动核对来源关系，删除停止作为当前来源；重启后补查变化；排除与撤回同时约束旧缓存和处理中任务 |
| US-2-008 | 我能控制材料处理，中断后接着处理未完成部分 | 工程代码与处理控制 | 有进度、暂停、取消、优先处理选定文件、单文件失败隔离和针对失败的重试；报告实际停止位置，保留完成状态；重启可继续未完成部分，不重复计为新材料；基础体积限制及超限反馈随格式接入交付，处理时笔记编辑仍可用 |

材料故事以虚构的项目材料集验收，不要求先建立项目入口。PDF、PPTX 是首批候选格式；样本与最终范围确认后再进入对应 spec。预览 Skill 可先随产品内置，无需等待第三方 Skill 安装能力。

### 材料格式与规模

| ID | 用户故事 | 主要承载 | 完成条件 |
|---|---|---|---|
| US-2-009 | 我能查找 Excel 中的内容，并看懂数值对应的表头、单位和位置 | 工程代码与工具＋预览场景 Skill | 代表工作表的文本、已有值与必要结构可查；说明公式与缓存值的边界；来源包含工作表和可核查区域，计算不能由模型口算冒充验证 |
| US-2-010 | 我能检索 Word 正文，并查看命中处的原文 | 工程代码与工具＋预览场景 Skill | 正文及必要标题/段落结构进入检索；可核查原件位置，表格等未覆盖内容明示，不承诺所有文件都有稳定页码 |
| US-2-011 | 我放入大量、较大文件后，可以先用已处理内容，并控制资源消耗 | 工程代码与处理控制 | 在事先约定的文件数、体积和设备样本下测量处理与编辑响应；已完成内容可用，支持优先处理选定材料、分批继续；未变内容不因恢复重复提取和索引 |

基础批量控制与格式接入共同验收；US-2-011 验证更大规模的调度、增量与资源表现，优先处理选定文件的基本操作由 US-2-008 共同验收。单文件上限及超限行为见材料分册，128 MiB 仅为待实测候选。格式扩展不默认加入 OCR、复杂图表理解、Excel 公式求值引擎或原生 Office 编辑。

| ID | 用户故事 | 主要承载 | 完成条件 |
|---|---|---|---|

| US-2-014 | 我能为一个主题建立可读的入口笔记 | 内置组织 Skill＋检索与笔记工具 | 入口按实际问题组织，链接到真实材料并说明用途；不复制所有材料正文，已有入口不被静默覆盖 |
| US-2-015 | 我能执行已确认的局部调整，并知道哪些已成功 | 内置组织 Skill＋可靠文件工具 | 只执行授权范围，核查移动后的引用和实际结果；部分失败明确报告；不能兑现的链接修复或恢复能力不声称成功 |
| US-2-016 | 材料增减后，我能按需刷新入口，保留自己的编辑 | 内置组织 Skill＋工具 | 用户主动要求时识别缺失、新增和失效引用，提出局部变化；保留手工说明，不以整篇重写覆盖用户调整 |

US-2-012、013、015 组成「诊断并改善局部组织」的完整验收单元，编号保留以追踪分析、选择与执行条件；不将三个流程步骤分别视为可独立交付的产品能力。US-2-014 建立入口与 US-2-016 刷新入口可独立使用。

组织收益用同一组查找任务比较：入口是否减少寻找和解释，链接是否有效，维护负担是否可接受。此处不包含从用户工作中提炼个人方法或生成用户 Skill。

### Skill 推荐、安装与使用

| ID | 用户故事 | 主要承载 | 完成条件 |
|---|---|---|---|
| US-2-017 | 我描述任务时，Agent 能找到已安装的合适 Skill | 工程发现工具与加载机制 | 中文代表任务可找到合适技能；技能较多时不因展示上限永久遗漏；保持按需读取，用户手动停用仍生效 |
| US-2-018 | 现有能力不够时，我能获得可核查的 Skill 推荐 | 内置推荐安装场景 Skill＋候选获取工具 | 优先检查已有能力，给出少量候选、来源、适用差异和所缺能力；复用生态发现能力，不伪造搜索结果或直接安装 |
| US-2-019 | 安装之前，我知道这个 Skill 在 Ratel 中能运行到哪一步 | 工程兼容性检查＋场景 Skill | 对工具、脚本语言、运行环境和资源需求给出已确认、缺失或未知；区分可加载与可执行；未知不标为兼容，不静默安装通用命令行环境 |
| US-2-020 | 我选择 Skill 后，能安装到指定范围并立即被发现 | 工程安装工具＋场景 Skill | 核对来源、目标范围和包内容，沿用有效授权；安装后可加载、可基本停用，记录可核查来源与采用版本或明确未知；失败保护随首次安装交付，不替换已有可用技能 |
| US-2-021 | Skill 用到参考文件、模板或较长说明时，Agent 能按需读取 | 工程资源工具与注入机制 | 代表 Skill 所需说明和资源可受控访问；大小限制或不支持项明确；不因正文截断无路回读，也不默认全量注入 |
| US-2-022 | 我能用推荐并安装的 Skill 完成一次实际任务 | 第三方 Skill＋Ratel 已有工具/受控 JS/已配置 MCP | 先选定有实际用户收益的任务与第三方 Skill 样本，明确工具、脚本和资源依赖，再验收推荐、兼容检查、安装、发现、资源读取及任务结果；依赖缺失和失败准确反馈，不将激活成功当作完成 |

US-2-018～022 按同一代表任务联合验收，任务与依赖未选定前不锁定通用兼容支持范围。首批第三方能力与来源待选择，推荐流程可参考成熟生态实现，但需核对许可证和实际运行依赖。安装与使用必须提供安装原子性、路径校验、权限和来源说明等最小保障；维护故事负责进一步的更新与维护，不补交安全底线。

### Skill 维护

来源版本的初次记录（US-2-023）、基本停用（US-2-025）与首次安装失败保护（US-2-026）同时属于 US-2-020 的交付底线。后续维护增强再验收更新比较、保留定制、移除及更新失败恢复，不将基础保障推迟交付。

| ID | 用户故事 | 主要承载 | 完成条件 |
|---|---|---|---|
| US-2-023 | 我知道 Skill 从哪里来、用了哪一版，以及是否值得更新 | 工程来源与版本记录＋场景 Skill | 版本信息有实际来源，未知如实标注；用户主动检查时展示可获得的变更和兼容性差异，不静默后台更新 |
| US-2-024 | 我修改过 Skill 后，更新不会悄悄覆盖我的改动 | 工程差异与冲突处理＋场景 Skill | 识别本地修改并提供保留、另存或明确替换选择；展示实际生效版本与同名覆盖关系，不默认自动合并 |
| US-2-025 | 我不想再用某个 Skill 时，可以停用或移除 | 工程管理工具与会话生效机制 | 明确停用对当前及后续会话的实际效果；移除核对范围与依赖，不误删知识材料和已产生成果；已有管理入口可复用，不重复建设 |
| US-2-026 | 安装或更新失败后，我能继续使用之前可用的版本 | 工程安装与恢复机制 | 部分下载、校验失败或加载失败不留半可用安装；失败可诊断并能重试；有可恢复版本时恢复并读回验证，不承诺撤销 Skill 已执行的外部操作 |

## 4. 共同验收约定

| 约定 | 执行含义 |
|---|---|
| 范围控制 | 首批格式、预览插件、第三方 Skill 与资源样本需确认；本清单提出候选而不替代选择 |
| 持续可发现 | 新材料未组织好仍可检索；组织 Skill 不能成为接入前提 |
| 能力状态 | 分别说明读取、原词查找、语义检索、原件查看、覆盖盲区和原件是否已变化；部分成功先用，状态不预设 UI 或存储 Schema |
| 搜索底座增强 | 链检索与反向追踪按真实链接和引用验收结果、方向及可核查位置；既有行为作回归，确认缺口后再设计增强，不另立产品故事 |
| 检索质量 | 按检索分册核对已知原词、语义召回、上下文、来源与反例；搜索底座和 Agent 使用结果分别验证 |
| 范围收回与缓存 | 收回范围后停止后续读取、检索和外发，取消可控的待处理及在途工作；已有派生文本和索引立即退出可用范围，清理或保留策略及完成状态可查；保留的副本重新启用前校验原件与权限。明确历史会话、既有成果和已外发内容的边界，不声称撤回即可抹除 |
| 基本一致性 | 每个格式交付时同时验证内容更新、位置变化、删除和失败，不推迟到后续批次 |
| 安全与隐私 | 每个故事沿用实际授权与外发边界；预览、提取、索引、Skill 下载和执行分别说明处理范围 |
| 异常反馈 | 覆盖不完整、部分成功和未知能力不报告为完成；一次成功不代表所有模型与材料可用 |
| 性能与成本 | 用约定样本测量，不以文件 MB 直接推算文本量、向量成本或质量；未知用量不显示为零 |
| 技术实现 | 故事确认后才拆 spec；这里不预选解析器、Schema、下载协议或新增运行环境 |
| 范围之外 | 无独立任务接续阶段、无用户方法提炼、无自动全库治理；来源依赖复核等旧候选不自动进入当前候选故事 |
