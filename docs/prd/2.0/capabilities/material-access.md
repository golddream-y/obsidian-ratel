# 材料接入与可用

> 2026-10-23 · 能力分册草案，待文档确认；不构成选型、实施或发布承诺。共同安全与验收原则见[总体 PRD](../README.md)。

## 1. 用户问题与范围

用户把笔记与办公材料放入 Obsidian 后，需要 Agent 能读、内容能查、自己能查看原件。材料可用由内容接入和原件查看共同构成，预览插件不能代替提取与检索，搜索成功也不代表原件能正常打开。不要求先整理整个知识库。

关联需求：`REQ-2-KS-001`、`REQ-2-KE-001`、`REQ-2-WS-001`。材料变化仅驱动内容与索引更新，不自动裁定知识结论失效；认识澄清、确认沉淀和结论演进仍在总体目标中待细化。

## 2. 内容接入要求

| 能力 | Ratel 负责什么 | 验证要求 |
|---|---|---|
| 材料范围 | 识别选定目录与文件，说明可处理、部分覆盖、失败和不支持内容 | 没有命中不等于未覆盖内容不存在相关信息 |
| 内容加工 | 原件生成可重建的派生文字，保留必要结构与定位信息 | 原件和派生内容身份可区分；不要求用户维护第二套笔记 |
| 统一检索 | 原词查找与语义检索使用可读内容，读取命中处上下文 | 办公材料不成为只能向量搜索的孤立附件入口 |
| 来源定位 | 返回真实原件及可核查位置，如页、幻灯片、工作表区域 | 不编造精确位置；跳转不支持时明确降级 |
| 文件一致性 | 修改后更新处理状态，重命名后核对来源，删除后停止作为当前有效来源 | 未完成更新时不把旧内容当作最新版 |
| 批量与大文件 | 按范围读取与检索，显示进度，支持取消、失败重试和中断后继续 | 不默认整件进入上下文或整件外发；日常笔记编辑保持可用 |

派生内容服务阅读、检索和定位，可以重建，不要求用户维护第二套笔记。文件修改、移动、重命名和删除需核对来源与索引，重启后补查变化；外部应用正在改写或锁定文件时明确当前不可用或可能不完整，不覆盖为虚假的成功状态。

**检索能力分层。** 可寻性由原词查找与语义检索共同提供，但两者不同级：

| 材料情况 | 底线 | 增强 | 不能声称什么 |
|---|---|---|---|
| 文字可提取（笔记、文本 PDF、Office 正文） | 原词查找必须成立 | 语义检索提升同义与模糊召回 | 缺语义索引时仍可说"可查"；缺原词查找则不可说"可查" |
| 无文字可提取（扫描页、图片、图表、嵌入对象） | 无原词可寻性 | 需另行说明所需能力（OCR、多模态等） | 文件进入索引不等于能查到；不能靠文件名冒充内容可寻 |

因此**向量化本身不是交付目标**，它只在提升可寻性时才有意义；没有语义索引，文字材料仍然可查。反之，非文本内容 grep 完全失效，若没有替代路径就必须如实标为不可寻，而不是收录后沉默。

### 能力状态与渐进可用

材料按已具备的能力渐进可用。用户与 Agent 能辨认正文是否可读、原词与语义搜索是否就绪、原件能否打开，以及内容覆盖和原件新旧状态。某个环节失败，不阻止其他已就绪能力继续使用；不得用单一「可用」掩盖未覆盖内容。

| 判断 | 需要说明的结果 |
|---|---|
| 正文读取 | 未处理、文字就绪、部分提取或失败，必要时提供原因 |
| 搜索能力 | 原词与语义分别说明是否就绪；语义索引未就绪时已提取文字仍可原词查找 |
| 内容覆盖 | 指出文字、备注、图片、图表等实际覆盖与盲区 |
| 原件变化 | 当前内容、原件已变更待更新或来源失效；旧内容不能冒充最新版 |
| 原件查看 | 是否可打开、可核查位置和精确跳转的实际支持 |

例如：「文字已就绪，原词可查；语义索引处理中。图片内容未识别。」这些是信息要求，不要求首页展示全部状态，也不预定存储字段或界面。

## 3. 原件查看要求

| 环节 | 场景 Skill 与已有工具负责什么 | 边界 |
|---|---|---|
| 识别需求 | 按用户材料格式和查看需求检查已有能力 | 用户收益是材料能查看，不是安装数量 |
| 选择查看方式 | 优先复用已有可用的查看方式；缺失时选择合适的格式预览插件 | 尚未指定具体插件；需另行核对维护状态、兼容性、隐私与实际覆盖 |
| 准备环境 | 通过现有生态工具检查、安装和配置所需插件 | 沿用授权；保留已有人工配置，不默认安装全部格式插件 |
| 打开原件 | 从材料或检索结果进入实际可用的查看入口 | 是否在 Obsidian 内查看、能否定位到页需逐项验证；外部查看仅作明确说明的降级 |
| 验证结果 | 用代表文件确认能打开、内容可见、来源位置可核查 | 安装成功不等于查看成功 |
| 异常与恢复 | 说明插件缺失、冲突、未支持内容及实际可恢复范围 | 回退依工具真实能力执行，不承诺完全撤销所有副作用 |

环境准备与日常查看分别验收。已有可用环境下，从检索结果打开原件不需要重复运行安装流程；PDF 页、PPT 幻灯片、Excel 区域及 Word 段落分别说明定位支持与降级。

查看环境可由内置场景 Skill 配合现有插件工具准备，不必等待第三方 Skill 在线安装能力完成。各格式插件的许可、维护、兼容性、网络行为和定位能力仍需验证；复用机制见[Skill 生态与能力扩展](skill-ecosystem.md)。

## 4. 格式覆盖与边界

| 材料 | Ratel 内容侧候选范围 | 用户查看侧需验证 |
|---|---|---|
| Markdown | 延用现有读取、检索和链接能力 | 延用现有笔记查看 |
| 文本型 PDF | 提取文字，保留页级位置 | 实际查看入口及页定位 |
| PPTX | 提取文字，保留幻灯片顺序；备注覆盖单独说明 | 预览幻灯片的实际效果；是否支持指定页 |
| Excel | 表头、单位、工作表与区域；区分公式及已有值 | 工作表、单元格和显示内容是否可核查 |
| Word | 正文及必要标题、段落结构 | 原件查看与可核查位置；不默认稳定页码 |
| 扫描件、复杂图表与嵌入对象 | 说明提取盲区，识别能力单独评估 | 可显示不等于模型已理解 |

这些格式是覆盖候选，不是已批准交付清单。每种格式分别记录可提取、可检索、可查看、可定位和可修改的范围；扫描件、复杂图表、嵌入对象和 OCR 不默认纳入。文字与必要结构先参与检索，不直接向量化整个二进制文件，不默认整件进入上下文或外发。

## 5. 安全、规模与失败恢复

沿用授权及排除范围，不因读取材料获得额外指令权限。来源被排除或权限收回后，停止后续读取、检索和外发，取消可控的待处理及在途工作；已提取文字和索引立即退出可用范围。后台处理完成也不得把被排除内容重新发布为可用。

既有派生文字、索引与其他缓存的清理或保留策略及执行状态需可查；保留副本重新启用前核对原件与权限。清理失败应报告，不以删除失败为由继续提供检索。历史会话、已生成成果和已外发内容的处置边界应明示，不能承诺范围收回即可抹除。具体清理时机与缓存机制在 spec 中确定。

基本批量控制随格式交付，包含进度、取消、针对失败的重试与中断继续；取消后报告实际停止范围。较大规模另用文件数、体积、设备与模型样本验证调度、资源和编辑响应，避免未变内容反复提取与向量化。容量、延迟和费用门槛待测量，不凭文件 MB 估算。

### 单文件体积门槛

材料接入先设一道体积门槛：**超过上限的文件不进入解析与索引**，如实告知"超限、未处理"，不静默截断、不把解析到一半的结果当作可用。门槛以内才展开后续方案——文字提取、语义保真、分块与向量化、变更后的更新触发、文本到原件位置的映射，均在此前提下再设计。

讨论中的候选上限为 **128 MiB**，**尚未实测，不是承诺值**。校准判据：

| 判据 | 要测什么 |
|---|---|
| 峰值内存 | 读入、解压、解析中间态与提取文本的合计，是否触发进程重启 |
| 界面可用性 | 处理期间 Obsidian 是否卡顿、崩溃或损坏已有索引 |
| 覆盖收益 | 上限以内能覆盖多少真实办公文件；被挡在门外的典型样本是什么 |

上限的数值与超限后的行为（直接拒绝、仅按需解析单页单表、或提示走外部处理）均为待确认项，进入 spec 前锁定。此门槛先作为产品要求讨论，不提前固化为技术架构参数。

### 规模与队列

规模档位本身也待定（千级、万级或更高由实测决定，见第 7 节）。无论最终落在哪一档，接入都不能是一次性全部处理的黑盒任务：它必须是可观察、可暂停、可恢复的持续过程。

| 要求 | 用户应看到的结果 |
|---|---|
| 渐进可用 | 已处理部分先参与检索；未处理部分不计入覆盖，结果说明本次实际覆盖范围 |
| 进度可读 | 已完成、待处理、失败、超限分别可见，剩余量有估计，而不是只有一个转圈 |
| 优先级 | 正在查看或检索命中的文件优先；用户可指定"先处理这个" |
| 暂停与取消 | 暂停后日常编辑照常可用；取消后报告实际停止位置，已完成部分保留 |
| 失败隔离 | 单文件失败不阻塞其余，可单独重试，不要求整批重来 |
| 中断恢复 | 应用关闭后重启接着处理，不从头再来，也不把已完成的工作重复计为新增 |
| 预期管理 | 首次接入大库可能耗时很长，开始前说明，不用"很快就绪"掩盖 |

实际吞吐、并发度与队列容量待实测，不在需求阶段虚构数字。调度策略、队列持久化形式与优先级算法属于后续 spec，本分册只约束用户可见的结果。
