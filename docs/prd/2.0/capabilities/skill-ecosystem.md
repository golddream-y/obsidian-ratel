# Skill 生态与能力扩展

> 2026-10-23 · 能力分册草案，待文档确认；不构成选型、实施或发布承诺。共同安全与验收原则见[总体 PRD](../README.md)。

## 1. 用户问题与范围

用户希望描述工作需要后，复用适合的方法、工具与配置，并确认它们确实可用。Skill 是承载机制，用户收益是任务与环境得到支撑。关联 `GOAL-2-001`、`REQ-2-WS-001` 和总体 PRD 的工作场景与 Agent 扩展底座；暂不新建独立需求编号或同义需求卡。

范围包括已安装能力发现、第三方推荐与安装、资源读取、运行兼容、来源与版本以及维护。不包含从聊天或工作中自动提炼个人方法、生成用户 Skill，也不默认扩展通用命令行或新增运行环境。

## 2. 产品能力与承载方式

| 产品能力 | 代码或工具负责 | 内置 Skill 负责 | 可选 Skill / 第三方负责 |
|---|---|---|---|
| 多格式内容可用 | 提取、分段读取、定位、处理覆盖与异常状态 | 按需说明处理范围和盲区 | 后续专项识别能力按实际支持接入 |
| 原词、语义与链检索 | 建索引、搜索、真实链接追踪、返回来源 | 组织具体查找步骤 | 专业研究流程可复用第三方 Skill |
| 文件变化与索引一致 | 变更检测、重命名与删除处理、增量更新和失效反馈 | 解释当前状态、引导继续 | 不交给 Skill 自行保证一致性 |
| 原件查看环境 | 插件状态、安装配置、打开文件及实际定位入口 | 场景 Skill 检查并准备所需预览环境 | 具体格式查看由合适的预览插件提供 |
| 知识组织 | 目录与属性查询、笔记读写移动、链接读取等原子工具 | 分析现有组织，提出调整并按授权执行、核查结果 | 专业领域的组织约定可选安装 |
| 知识入口与索引笔记 | 检索真实文件和链接，执行可靠读写 | 生成或更新入口内容，控制粒度和维护范围 | 允许采用其他组织方案，不强制全库模板 |
| 推荐合适 Skill | 返回可核查候选来源及实际可获取的信息 | 按需求筛选、解释适用性和所缺能力 | 复用成熟发现能力与第三方 Skill 目录 |
| 安装与启用 Skill | 获取文件、路径和内容校验、来源记录、加载及启用状态 | 编排选择、安装和结果核查 | 上游提供 Skill 包，不要求 Ratel 重写其中方法 |
| 第三方 Skill 执行 | 能力与依赖检查、权限、脚本沙箱、工具或 MCP 连接 | 说明可运行范围，调用可用工具 | 通用研究、写作、文档等能力逐项验证兼容性 |
| Skill 更新维护 | 版本识别、差异、覆盖冲突和实际回退能力 | 引导选择更新、保留定制或停用 | 尊重来源与许可证，不默认批量升级 |

上述材料与组织能力的详细产品要求分别见[材料分册](material-access.md)、[检索分册](knowledge-discovery.md)和[组织分册](knowledge-organization.md)，本表只说明协作边界。内置表示通用入口随产品交付，可选表示按需安装，不要求用户自己编写 Skill。

AGENTS.md 表达有作用域的工作约定，MCP 连接外部工具，目标与任务管理使用已有机制；本轮不借生态扩展另设独立任务接续阶段或承诺多模型自动路由。第三方 Skill 采用的宿主工具、权限与运行环境必须映射为 Ratel 实际能力，不能因同名而假定语义一致。

## 3. 现有基础与增强候选

| 支撑能力 | 当前静态核对结果 | 需要评估的增强 | 服务哪项产品能力 |
|---|---|---|---|
| 加载与启用 | 已有内置、全局和库内三源加载，以及逐项启用 | 安装后可靠重载、来源和同名覆盖可辨认 | 内置与可选 Skill 交付 |
| 发现与按需读取 | 已注入名称描述，激活正文、读取参考文件；发现列表有数量上限，中文匹配较弱 | 按任务查找更多已安装 Skill；改进中文发现，避免被列表截断遗漏 | 少配置即可找到合适能力 |
| 正文和资源 | 激活正文有大小上限，参考文件已有受控读取 | 验证长正文回读及模板、资源访问能否支撑实际第三方 Skill | 第三方兼容与组织场景 |
| 导入与安装 | 已有管理与重载入口；本次核对未确认端到端在线 Skill 安装能力 | 来源获取、目标范围、文件校验、来源与版本记录、加载结果 | 推荐安装场景 Skill |
| 运行依赖 | 已有受控 JS 脚本、信任门与 MCP 能力 | 安装前识别所需工具、运行环境与资源，明确可用、缺失和不兼容 | 第三方 Skill 可执行性 |
| 执行与权限 | 脚本限定 JS；执行环境不是通用命令行 | 优先复用现有工具和已配置 MCP；新增运行环境需单独决定 | 不把“可加载”宣传为“可运行” |
| 更新与定制 | 当前来源分层不能替代更新与覆盖策略 | 版本差异、本地修改冲突、更新选择及实际回退 | 长期维护可选能力 |

这些结果来自前次代码静态核对，不是本次运行验收。安装与执行的权限、路径校验、内容和状态一致性由工程保证；Skill 负责筛选、解释和编排。「可加载」「可执行」「任务完成」分别核查，不将激活成功当成结果成功。

## 4. 安全、维护与失败恢复

推荐先检查已有能力，候选来源可核查；下载、安装、资源获取、脚本运行和 MCP 外发分别遵守授权，未知依赖不标成兼容。核对来源与许可，不把可阅读源码直接视为可自由打包分发。

首次安装即记录来源与采用版本或明确未知，提供基本停用和失败保护。这些能力分别引用 US-2-023、025、026，但随 US-2-020 一起验收。后续维护再扩展到更新比较、本地定制、移除及版本恢复。

安装与更新不能留下半可用状态或静默替换已有能力。更新前识别本地修改与同名覆盖，允许保留、另存或明确替换；不默认后台批量升级。停用和移除说明对当前及后续会话的效果，不误删知识材料与已生成成果。能恢复安装版本不代表能撤销 Skill 已执行的外部操作。

## 5. 验收与故事覆盖

| 故事 | 可检查结果 |
|---|---|
| US-2-017～018 | 中文任务和较多技能下可发现合适能力，缺少时给出真实且少量的推荐 |
| US-2-019～022 | 兼容检查、安装、资源读取和一次代表任务均有真实结果与失败反馈 |
| US-2-023～026 | 来源版本可辨认，更新保留定制，停用移除及失败恢复范围准确 |
| US-2-006 | 内置场景 Skill 准备实际可用的查看环境，可先复用已有插件工具 |

安装原子性、权限、校验和失败保护属于最小保障，不能等维护批次再补。先选择能提供实际用户收益的第三方任务与样本，列明工具、脚本及资源依赖，再联合验收 US-2-018～022 的推荐、兼容检查、安装、发现、资源读取与任务结果。不能先建设通用安装能力，再用任意可加载样本代替任务验收。首批样本与来源仍待选择。

具体条件见[用户故事](../stories/README.md)，批次只在[路线](../../../roadmap/2.0.md)维护。
