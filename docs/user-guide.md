# Ratel 使用手册

[English](user-guide.en.md) · **简体中文**

本手册带你完成第一次检索，再按需要整理笔记、搭建插件环境、使用日记工作流和继续长期任务。Ratel 在 Obsidian 桌面端运行，需要 1.13.1 或更新版本。

先完成[安装与首次提问](#1-安装并完成第一次提问)。已经配置好模型，可以直接选择任务：

- [找回笔记与写综述](#2-查找理解和整理笔记)

- [安排今天、收尾与月末复盘](#4-安排今天收尾和月末复盘)
- [记忆与长期目标](#5-记住工作约定继续长期任务)

## 1. 安装并完成第一次提问

首次使用的顺序是：安装插件 → 配置对话模型 → 检查权限 → 等待索引 → 提问并核对来源。你不需要预先整理标签或链接。

### 安装与模型配置

1. 在 Obsidian **设置 → 社区插件 → 浏览**搜索 **Ratel**，安装并启用。
2. 打开 **设置 → Ratel → 对话模型**，在“已保存的配置”中点击标为“当前”的一行。下一页先选择提供商，再选择模型；本机 Ollama 位于本机分类，常用提供商中可以搜索火山或 DeepSeek。使用自定义端点时填写 API Base 和模型名。模型以服务或本机实际可用的为准。
3. 使用远端服务时，在这套配置的“API 密钥”中填写 API Key，系统会自动同步到 Obsidian 钥匙串加密保存，无需另行手动添加。本地 Ollama 的 API Base 通常是 `http://localhost:11434/v1`，无需密钥，但需要先启动 Ollama 并准备对应模型。
4. 查看 Ratel 设置中的密钥状态。模型调用的费用由你选择的服务收取。

需要保留另一套对话配置时，回到“已保存的配置”，点击“另存当前配置”。聊天窗口顶部的模型名可以切换配置，每套配置有独立密钥。

默认嵌入在本机运行。首次需要下载模型和 WASM 运行资源，再建立笔记索引；这期间可以继续使用 Obsidian。聊天输入区上方的状态条会显示进度，未就绪时会提示阻挡发送的原因。

### 检查操作权限

**内置工具默认“允许”，包括笔记写入、删除和插件配置。安全档不会把设为“允许”的工具改成逐次询问。**

如果希望先审查每次修改，打开 **设置 → Ratel → 记忆与权限 → 工具权限**，把写入、追加、编辑、删除及插件变更工具设为“询问”，并保持安全档。各档位的完整行为见[权限说明](#7-控制权限与数据外发)。

### 完成第一次检索

点击侧栏 🦡 打开聊天，选择库里确实存在的一个主题，输入：

> 找出库里关于项目复盘的笔记，简要说明每篇写了什么，列出来源。先不要修改文件。

回答后，点击正文引用或展开来源列表，打开原笔记，核对是否相关、总结是否准确。能得到相关笔记并打开来源，就完成了第一次使用。找不到时，试试笔记中的原词，或用 `@` 选择一篇已知笔记再提问。

## 2. 查找、理解和整理笔记

### 找回与阅读

你可以按主题提问，也可以指定当前笔记、文件、标签或属性。用库内相对路径定位文件；输入 `@` 可补全笔记，文件列表里右键 Markdown 文件也可以“添加到 Ratel”。指定路径不会预先把整篇内容塞进输入框，助手会按需读取。

| 任务 | 示例输入 | 检查结果 |
|---|---|---|
| 模糊找回 | 我写过哪些关于缓存失效的笔记？ | 来源是否对应你要找的内容 |
| 理解当前笔记 | 总结当前这篇，列出还没解决的问题 | 结论能否在原文中找到依据 |
| 查看关系 | 谁链接到这篇？这篇有哪些未解析链接？ | 打开相关笔记检查关系 |
| 筛选笔记 | 找所有标签为 project、状态为 draft 的笔记 | 标签和属性是否符合条件 |
| 打开位置 | 打开 `Projects/Plan.md` 的第二章 | 是否跳到指定标题或块 |
| 查看近期工作 | 最近修改了哪些笔记？ | 文件和时间是否符合预期 |

引用是来源入口，不代表结论一定正确。涉及重要判断时，请打开原文核对。没有打开笔记时，“当前这篇”无法定位，改用 `@` 或文件路径。

### 从多篇笔记写出文档

把范围、产物和写入要求一起说清：

> 从 Projects/Example 下的笔记整理项目背景、关键决策和待确认问题。保留来源，先在对话里给草稿，不修改文件。

检查草稿是否遗漏重要材料、把推测当作事实或引用了无关笔记。满意后再说：

> 把这份草稿写到 Projects/Example/背景综述.md；如果已有内容，先读出来，说明准备修改哪些段落。

工具执行会显示在对话中，是否弹确认取决于权限设置。完成后打开目标文件，检查内容、链接和修改范围。插件环境的恢复备份不等于笔记版本历史；普通笔记修改应使用你自己的备份或版本管理。

已有笔记的局部修改使用原文片段精确替换；需要移动或复制时直接说明源路径与目标路径。工具返回修改后的汉字数和拉丁词数，可让助手据此核对篇幅。笔记目录及上级目录中的 AGENTS.md 会作为写作约定，修改约定文件仍需确认。需要修改同一篇笔记的多处内容时，也可以使用补丁编辑；所有修改匹配成功后才写入，格式错误会给出行号和纠正指引。工具参数失败时会给出对应纠错信息，残缺参数不会执行。

## 3. 安装和维护插件环境

### 配好日记场景

内置场景适合希望用日记记录工作时段、用月度台账跟踪目标的用户。输入：

> 装好日记和月度复盘环境。

也可以输入 `/install-diary-plugins`。选择技能后，它先进入输入框，再按回车发送。

Ratel 会说明拟执行的安装和配置，询问日记根目录，默认建议 `Work/Diary`。确认前检查目录是否适合现有库。英文界面下，技能会询问是否翻译中文模板标题和提示。

确认后，技能按需安装 Templater、Dataview 和 Day Planner，写入日记、月度模板，配置核心日记和相关插件，并记住日记与台账位置。已有模板不会直接覆盖；如果指定目录已有平铺的日记，技能可能将其移入月份目录，请留意执行说明。

完成后检查：

1. 模板文件存在，日记目录符合你的约定。
2. 用 Obsidian 核心日记功能创建或打开当天日记，检查模板是否生效、当月台账是否存在。安装技能本身不新写当天日记。
3. 在“🧸 今天的任务记录：”下写一条带起止时间的任务，确认 Day Planner 能显示。

**修改 Day Planner 标题后，要完全退出 Obsidian 再打开；仅重载插件或应用不足以生效。** 这套工作流用到 Dataview JS，请在确认安装方案时了解这一设置。

### 管理其他插件

可以从需求出发让 Ratel 推荐，也可以点名插件：

> 找一个适合项目看板的社区插件，说明选择理由，先不要安装。

> 查看 Dataview 当前状态；把我点名的设置改掉，保留其他配置。

Ratel 支持搜索、安装、更新、卸载和按字段修改配置。来源限定为官方社区清单中的插件，不安装你随手提供的下载 URL；不代填密钥。安装后若不能即时启用，按结果提示重载，再检查实际功能。

### 查看变更与恢复

插件变更会记录动作和恢复备份。需要撤回时，先说：

> 列出最近的插件变更，说明每次改了什么。

从记录中选定具体变更，再要求恢复。恢复会把对应快照写回；若之后又改过该插件，较新的修改可能被覆盖。备份过期时无法恢复，不要把变更备份当作整个库的长期备份。

恢复后重新加载应用，并在目标插件里检查版本、设置和启用状态。日记场景包含模板、记忆和宿主设置等多项操作，恢复某个插件的备份不等于撤销整个场景。

## 4. 安排今天、收尾和月末复盘

先完成日记环境配置，或告诉 Ratel 你已有的日记和月度台账在哪里。输入 `/diary-month-ledger` 可以明确调用内置工作流，也可以直接说出下面的任务。

| 时机 | 输入 | 读取与产物 |
|---|---|---|
| 开始工作 | 安排今天的工作 | 读取月目标和昨日遗留任务，起草今日工作时段 |
| 当天收尾 | 同步今天的台账 | 从今日任务时段提取记录，追加月台账并更新目标进展 |
| 月末 | 做本月复盘，起草下月目标 | 汇总日记和台账，写复盘草稿；确认后流转未完成目标 |

技能会先读取相关记录，说明要修改哪些文件、各改什么，等你确认再连续写入。当天工作时段写在“🧸 今天的任务记录：”下，例如 `- [ ] 08:50 - 10:50 整理项目材料`；日记正文由你维护，收尾同步不会改掉这些细任务原文。

完成后检查日期、时间安排、关联目标和状态。月度台账保存粗粒度进展，日记保存当天细节。未完成目标只有在你同意后才流转下月。

找不到日记或约定不清时，先定位目录并更新记忆。安装后的核心日记可能按年、月分目录，不能只在根目录查当天文件。单独询问“今天日记在哪”只探测位置，不自动创建。

这些操作需要你发起。定时主动简报、洞察收件箱和自动知识治理尚未交付。

## 5. 记住工作约定，继续长期任务

### 记录和纠正记忆

> 记住：项目资料放在 Projects；输出综述时保留来源，先给草稿。

之后可以问“你记住了哪些项目约定”，或要求修改、忘掉某条约定。打开 **设置 → Ratel → 记忆与权限 → 查看记忆**，也可以在聊天状态抽屉进入记忆管理，直接浏览、编辑和清理。

记忆默认启用，自动写入也默认开启；不希望自动记录时，在同一设置页关闭。记忆用于模型上下文，不能替代工具权限或保证模型每次都遵守。

记忆保存在库内普通 Markdown：`.ratel/memory/global.md` 保存全局约定，`topics/` 保存主题记忆，`index.md` 是主题索引。可以直接编辑。全局注入有容量限制，重要段落标题可加 `[pinned]`；相关主题自动注入条数可在设置中调整，设为 0 即关闭主题自动注入。

### 建立和继续长期目标

适合多轮整理任务。例如：

> /goal 检查 Projects/Example 下的笔记，补全缺失的 status 属性；已有属性不改，完成后列出修改文件。

助手会先与你确认完成标准和回合上限，再创建目标。同时只能有一条未完成目标。`/goal` 不支持 `30m`、`2h` 这样的限时前缀。

目标保留在库里，状态条会显示进行中、暂停、受阻或回合预算用尽。换到新对话后，点击“接管”把目标绑定到当前对话再继续；新对话不会自动拥有旧对话的完成标准。

停止当前生成与暂停目标是两件事。暂停、恢复、放弃和归档可以在状态抽屉的目标列表，或 **设置 → Ratel → 记忆与权限 → 查看目标**中操作。暂停会收回目标的目录授权。

回合用尽时，可以增加当前目标的回合数或先停下来；设置里的默认回合上限只影响以后创建的目标。完成后核对标准和文件，再在对话中确认结束。Goal 不等于定时任务，也不在 Obsidian 关闭后继续运行。

## 6. 管理会话与使用扩展

### 会话和图片

右上角标题按钮打开历史列表，可以恢复旧对话、新建或删除；旁边的编辑按钮可以修改标题或让 AI 总结标题。生成中切换会话会先确认并停止当前回复。关侧栏或重启后会回到上次会话。

`/new` 开新对话；`/compact` 压缩发给模型的上下文，保留界面里的聊天记录。上下文接近上限时默认自动压缩，可在对话模型设置关闭。重要约定可以存入记忆，长期任务用 Goal 保留完成标准。

输入区可附图片，需要同时输入文字。图片会发给当前对话模型；它必须支持视觉输入，纯文本模型可能报错。图片在本机保存，重启后历史仍可查看。

### 使用和管理 Skill

Skill 是一套可复用的做法。内置技能覆盖日记安装、日常台账和 Ratel 配置；可以在对话里点名，也可以在 `/` 菜单选择。

安装自己的技能时，将含 `SKILL.md` 的文件夹放到库内 `.ratel/skills/`，或用户主目录下 `.ratel/skills/`，然后重新加载插件。库内同名技能优先。状态抽屉中的“技能”面板可查看来源、启停、编辑或删除；内置技能随插件更新，不能直接编辑。

技能可附 `references/` 文本资料和 `scripts/` JavaScript 脚本。脚本在沙箱中运行，无网络，不能加载外部模块，不能访问 Obsidian 配置目录；库外访问开关不会放宽脚本沙箱。首次运行会询问信任，可选“允许并记住”“仅此次”或“拒绝”。

无进度的脚本默认 30 秒超时，有进度的长任务可继续等待，但最长 10 分钟。连续失败 3 次会阻止继续执行，需要重新确认授权。无响应超时可在高级设置调整。完整制作方法见[场景技能手册](contributing/scene-skill.md)。

### 连接 MCP

在状态抽屉打开 **MCP** 管理，添加 HTTP 或本地命令服务器，也可以导入 Claude / Cursor 格式的 JSON 配置。先检查服务器来源、命令和数据去向，再启用；本地命令服务器可能启动进程，远端工具会将参数发送给其服务器。

启用后，工具进入对话，并受各自权限控制。默认外部工具询问；自动档仍保留高影响工具的询问规则，危险档会跳过。需要网页搜索等能力时，配置提供该能力的服务器。连接失败或无工具时，等待启用完成，再“刷新”重连。

## 7. 控制权限与数据外发

### 工具权限

在输入区下方或 **设置 → Ratel → 记忆与权限**选择档位，并为单个工具设置允许、询问或拒绝。

| 档位 | 没有额外授权时的行为 |
|---|---|
| 安全 | 遵循单工具设置：允许则执行，询问则确认，拒绝则阻止 |
| 自动 | 普通工具可直接执行；删除、插件变更、库外访问、MCP 等高影响工具仍遵循单工具设置 |
| 危险 | 跳过询问，但设为拒绝的工具仍不能执行 |

**出厂内置工具大多设为允许，包括写入、删除和插件变更。** 想每次审查这些操作，必须把它们改为询问并选择安全档。自动档会放行普通写入工具，即使其设为询问。

确认弹窗的“本次会话不再询问”按工具名授权，不限单个路径；换会话或 `/new` 后清空。Goal 的目录授权也可能减少确认。想收回目标授权，暂停目标；单工具拒绝始终优先。技能中的“先确认”是工作流程约定，强制拦截依赖权限设置。修改 `AGENTS.md` 的操作另有强制确认，不因允许、危险档或已有授权跳过。

### 库外文件与本机命令

“允许访问库外”默认关闭，只能在设置中手动打开，对话配置不能代开。打开后，可以列目录、读库外文本、原样导入文件和运行本机命令；这四项默认询问，在安全档和自动档下按工具设置与已有授权处理。危险档会跳过询问。

从系统文件管理器复制的绝对路径可以贴到输入框，但不会被当作库内笔记。读出的内容可能进入模型上下文。本机命令可能有文件或网络副作用，确认时检查实际命令和工作目录。关闭开关后，这些库外工具再次被阻止。

### 数据存储和网络连接

| 场景 | 数据位置或去向 |
|---|---|
| 索引、会话、附件和诊断 | 保存在本机插件目录；无遥测，诊断不包含笔记正文 |
| 记忆 | 库内 `.ratel/memory/`；相关记忆会用于对话上下文 |
| 对话模型 | 问题、选取的笔记内容、记忆、工具结果和附件可能发往配置端点 |
| 远端嵌入或重排 | 启用时，相关笔记文本或候选片段发送给对应端点 |
| 首次本地嵌入 | 从 ModelScope 下载模型，从 jsDelivr 下载 WASM 运行资源 |
| MCP | 已启用服务器的连接，以及工具调用参数；数据边界取决于该服务器 |
| 插件安装与更新 | 官方社区清单、所选插件的 GitHub release |

对话模型密钥在模型设置界面填写后，自动同步到 Obsidian 钥匙串加密保存，不写入 Ratel 的 `data.json`，Agent 不会代填。默认本地嵌入不意味着远端对话离线；使用本地 Ollama、已下载的嵌入资源且不调用外部工具时，可在本机处理。

全库黑名单尚未交付。对不能发给远端的资料，不要仅依赖一次提问中的范围约定；选择合适的本地模型或使用分开的库。

## 8. 排障与速查

### 按现象处理

| 现象 | 处理顺序 |
|---|---|
| 不能发送 | 查看输入区上方原因；检查密钥、模型端点和索引状态 |
| 首次索引迟迟不完成 | 检查资源下载与网络；展开状态条查看索引和嵌入状态，再查看诊断 |
| 模型调用失败 | 核对 Base、模型名、密钥和服务额度；本地 Ollama 检查进程和模型 |
| 找不到已知笔记 | 用原词或 `@` 路径确认文件；只索引 Markdown；必要时重建索引 |
| 改了嵌入模型或分块没生效 | 重启 Obsidian，再检查索引；需要时执行 `/reindex` |
| 日记模板或时间轴没生效 | 检查模板、核心日记目录和相关插件配置；Day Planner 改标题后完全退出再打开 |
| 插件变更后行为异常 | 列出变更记录，选具体备份恢复，再重载检查 |
| 问了却没有确认弹窗 | 检查单工具是否允许、档位、会话授权和目标目录授权 |
| 新对话不能继续旧目标 | 点击接管；检查是否暂停、受阻或回合用尽 |
| 引用打不开 | 悬停检查来源路径，确认笔记仍存在；重新检索后核对 |
| 带图后请求失败 | 当前模型可能不支持视觉；移除图片或换视觉模型 |
| MCP 没有工具 | 等待启用完成，检查服务器配置后刷新 |

网络重试会显示在聊天底部，点停止可中断等待。状态条展开后可查看索引、嵌入和上下文占用，并进入目标、记忆、技能、MCP 与反馈。

反复失败时，到 **设置 → Ratel → 高级 → 诊断**查看“上次运行”；反馈入口可复制本地诊断。提交 Issue 前检查诊断中的环境信息，附上复现步骤和错误提示。

### 命令与设置

| 输入 | 用途 |
|---|---|
| `/new` | 新对话 |
| `/goal 目标陈述` | 确认并创建长期目标 |
| `/compact` | 压缩模型上下文，保留聊天记录 |
| `/model` | 查看模型配置 |
| `/reindex` | 全量重建索引 |
| `/install-diary-plugins` | 内置日记安装技能 |
| `/diary-month-ledger` | 内置晨间、收尾、月末技能，可补充任务描述 |

前五项是固定命令，后两项来自启用的技能。选择技能或 `/goal` 后先补充内容、再发送；无参数命令选中即执行。命令面板另有打开聊天、显示索引状态、暂停／恢复自动索引和清空索引。

| 设置页 | 用途 |
|---|---|
| 对话模型 | 语言、已保存的配置（提供商、模型、地址、API 密钥和上下文长度）、自动压缩 |
| 笔记索引 | 嵌入、分块、自动索引、可选重排 |
| 记忆与权限 | 记忆、日记约定、目标、工具权限、库外开关 |
| 外观 | 配色、强调色、消息导航、动效和捣蛋鬼 |
| 高级 | 上下文长度、模型登记、提示词覆盖、脚本超时和诊断 |

界面语言可选自动、中文或英文；命令面板名称需要重启才刷新。消息区边缘的点列可跳转提问，离开底部时点向下按钮回到最新。

### 密钥存储名称（排障参考）

对话密钥在“已保存的配置”中打开对应配置后填写，自动同步到钥匙串加密保存。每套配置有独立密钥，页面显示的存储名称仅用于检查，不需要再创建同名条目。

嵌入、重排和 MCP 密钥仍需在 Obsidian **设置 → 钥匙串**中按下面的名称添加：

| 名称 | 用途 |
|---|---|
| `ratel-embed-openai-compatible` | 启用远端 API 嵌入时 |
| `ratel-rerank-bailian` | 可选百炼重排 |
| `ratel-mcp-<serverId>` | 本地命令 MCP 服务器的密钥环境变量，ID 取自管理页 |
