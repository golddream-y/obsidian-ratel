# 运行时资产下载

> 领域:宿主 | 模型与推理引擎的下载、重试、校验与失败处理
> 相关:[嵌入推理的分层执行](../llm/embedding-inference.md) 说明这些资产被谁使用

---

## 职责

说明插件在首次使用本地嵌入时,需要下载哪些文件、从哪来、怎么重试、失败会怎样,以及用户能看到什么。

**不做的事**:

- 不负责远端 API 模式(不下载模型,见[模型管理](../llm/model-management.md))
- 不负责模型的选择与切换策略
- 不负责索引数据的落盘(见[向量索引子系统](../rag/vector-index.md))

## 网络边界

发版产物只有 `main.js`、`manifest.json`、`styles.css` 三个文件,模型和推理引擎不可能随包分发,只能在首次使用时下载并缓存到插件目录。因此「安装后完全离线可用」不成立:首次启用本地嵌入必然产生网络请求。

| 资产 | 文件 | 体积 | 用途 |
|---|---|---|---|
| 嵌入模型 | `model_quantized.onnx` | 约 24 MB | 向量化模型本体 |
| 模型词表 | `vocab.txt` | 约 109 KB | 精确 token 计数 |
| CPU 引擎 | `ort-wasm-simd-threaded.wasm` | 约 13 MB | CPU 推理运行时 |
| GPU 引擎 | `ort-wasm-simd-threaded.asyncify.wasm` | 约 23 MB | WebGPU 推理运行时 |

两份引擎不会同时下载:GPU 可用时只下 GPU 那份,回退到 CPU 时才补下另一份,详见[执行器如何选定](../llm/embedding-inference.md#执行器如何选定)。

## 统一下载机制

模型文件与两份推理引擎共用一套实现(`src/core/asset-downloader.ts`),差异只在镜像清单。这一点是刻意收敛的结果:早先模型、CPU 引擎、GPU 引擎各写一套,导致模型下载不原子、CPU 引擎只有单源无重试。

| 能力 | 做法 |
|---|---|
| 多源回退 | 每个资产声明按优先级排列的镜像,前一个失败才试下一个 |
| 逐源重试 | 每个镜像默认尝试 2 次;网络异常与 HTTP 状态码失败同等对待 |
| 原子落盘 | 先写 `.downloading` 临时文件再 rename,中断不会留下半截正式文件 |
| 完整性校验 | 结果小于最小字节数即视为失败,继续换源 |
| 进度上报 | 按尝试阶段上报 0–1 进度,由调用方决定怎么展示 |

## 镜像清单

所有镜像都指向同一个开源包的同一份文件,只换托管位置,不引入新的数据去向。

| 资产 | 国内源(优先) | 国际源(兜底) |
|---|---|---|
| 模型与词表 | ModelScope | HuggingFace |
| 引擎 | npmmirror | jsDelivr |

## 顺序如何决定

不用界面语言或地区判断:中文界面可能出现在国外,英文界面也可能在国内,两者与真实网络位置没有稳定关系。改为按以下优先级:

1. **历史成功过的源** —— 上次谁成功就先用谁。这是最可靠的信号,直接反映当前这台机器的网络
2. **没有历史时并行测速** —— 各镜像取前 128 KB 做 Range 请求,3 秒超时,选响应最快的一个
3. **测速也失败** —— 回落声明顺序,即国内优先

第 2 步用 Range 而不是 HEAD:HEAD 只有响应头,反映的是首字节延迟,与真实吞吐无关,就近的边缘节点可能延迟很低却限速严重。取一小段真实字节能同时体现延迟与初始吞吐。

测速结论只用于首次决定顺序,之后一律以历史记录为准,不重复测速。128 KB 的吞吐未必等于 23 MB 的全程吞吐,所以它只是首次的启发式判断,不是持续评估。

偏好按资产类别分别记录(`model` / `ort`),存在插件目录的偏好文件中;该文件读失败或损坏时视为无记录,不阻断下载。

## 能力门控:先探测再下载

GPU 引擎有 23 MB,在明确用不上的机器上不该下。启动顺序因此是:先调 `requestAdapter()` 判断能力,再决定下载哪一份引擎。

- 没有 `navigator.gpu`、拿不到适配器、或只拿到软件适配器 → 不下 GPU 引擎
- 有硬件适配器 → 只下 GPU 引擎,跳过 CPU 那份
- GPU 探测后续失败 → 补下 CPU 引擎并提示用户

软件适配器(SwiftShader 一类)按不可用处理:它让「支持 WebGPU」变成假象,实际速度不如 CPU,却要先付 23 MB 下载成本。

## 用户可见信息

| 时刻 | 用户看到 |
|---|---|
| 下载 GPU 引擎 | 正在下载 GPU 运行时(约 23 MB,N%) |
| GPU 引擎下载失败 | GPU 运行时下载失败,本轮改用 CPU 推理 |
| GPU 探测失败后补下 CPU 引擎 | 正在下载 CPU 运行时(约 13 MB) |
| 下载模型 | 进度提示,沿用模型加载阶段的进度显示 |

失败一律降级而不是中断:引擎下载失败只意味着这一轮用 CPU,索引与检索照常可用。这一点曾经是缺陷 —— 早期实现让 GPU 引擎下载失败向上抛出,整个嵌入代理建不起来,索引直接不可用。

## 缓存与失效

资产下载后缓存在插件目录,按文件是否存在与最小字节数判断有效性,命中缓存不再联网。删除缓存文件即触发下次重新下载。

推理引擎的版本与 `package.json` 中的 `onnxruntime-web` 版本同步,升级依赖时文件名与内容可能变化,缓存需重新获取。
