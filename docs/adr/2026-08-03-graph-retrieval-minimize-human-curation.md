# ADR-013:图谱检索默认「少靠人整理」— 向量保底 + 机会性用边

**状态**:Accepted  
**日期**:2026-08-03  
**关联**:
- [S-EVOLUTION](../superpowers/specs/2026-07-15-evolution-graph-agent.md)(图谱原生 Agent 总纲)
- [P-EVO-A-READ](../superpowers/plans/2026-07-15-evo-a-read.md)(链接 / tag / 结构信号读工具)
- 既有混合检索(向量 + BM25;`search_vault`)— 本 ADR 定「图边」在产品与工程上的质量立场

---

## Context(背景)

产品对外称「图谱原生」:相对通用文件聊天,应吃到 Obsidian 双链 / 反链 / 标签等结构。

讨论中已达成技术共识(Hybrid):

1. **向量**负责语义召回(「像不像」)
2. **图**负责扩邻、补背景、可解释出处(「连没连上」)
3. 回答应带可点引用

但随之出现产品级分歧:

| 立场 | 含义 |
|---|---|
| **A. 图质量靠人养** | 要求用户少孤儿笔记、正文多链、标签纪律;图检索才「真好用」 |
| **B. 尽量避免人管理** | 不把「先整理库」当使用前提;图是增益,向量保下限 |

Obsidian 的 wikilink / 反链 / 标签**可以**当作图关系,但语义是「笔记导航 / 人声明的关联」,**不是**消歧后的领域知识图谱(人物—任职—公司一类)。边密度与边质量确实高度依赖个人习惯;若产品话术暗示「你整理得越好 AI 才越强」,会抬高门槛,与 Ratel「默认本地、少折腾」不符。

### 反例:不能依赖「人养边」或「Obsidian 自动关联」

真实使用中常见 **日计划 / Daily Note 当枢纽**:

- 每天自动开一篇「当日状态」笔记
- 当天打开过的笔记会**大量自动挂到这篇日记**(插件或工作流写回链)
- 结果:图上边很多,但语义是「今天点开过」,不是「知识上相关」

因此:

1. **不能把「人整理得好」当前提** — 很多人的边是工作流噪声,不是精心声明的概念关系
2. **也不能把 Obsidian / 插件的自动关联当金边** — Daily hub、MOC、模板狂链会刷爆反链度中心性;按反链扩邻等于把「今日打开过的一切」塞进上下文
3. **metadataCache 仍有用** — 给 Agent **显式工具**按需查链接 / tag;默认检索主路径仍须 **向量(+BM25)保底**,图边默认降权或仅机会性使用

业界对照(2026-07 Tavily 调研摘要):

- 纯向量:单跳相似段落强;多跳 / 关系问句弱
- GraphRAG / Hybrid:多跳与可解释性更好,但全库抽实体建 KG 成本高
- Obsidian 生态实践:有链接则 agent 可跳 hop;无边则退化为普通检索 — **图是杠杆,不是准入证**

---

## Decision(决策)

### 1. 默认立场:**尽量避免人管理**

- **不采纳**「用户必须先养好链接图才能用好检索」作为产品前提
- **采纳**:向量(+既有 BM25 混合)保证**无人整理库也可问答**;有链接 / 标签时**机会性**用边增强,无边则静默跳过扩邻
- 对外表述:「在你已经链起来的地方能顺着关系办事」,**不是**「请先变成图书管理员」

### 2. Obsidian 边的角色界定

| 信号 | 定位 | 工程默认 |
|---|---|---|
| 正文 wikilink / 已解析出链 | 声明边;**也可能是日记自动回写** | 扩邻可用;对 **Daily / hub 出链扇出** 降权或截断 |
| 反链 | 中等;易被 MOC / **日计划枢纽** 刷屏 | 可用,但对超高反链 hub **强降权**,不默认「反链越多越相关」 |
| 标签 | 弱分类 / 粗过滤 | `search_by_tag` 等显式工具;不默认当强逻辑边 |
| 未解析链接 | 知识缺口信号 | 可读工具暴露;不假装已存在节点 |
| Obsidian/插件自动关联 | 工作流边,常无主题语义 | **不当作高质量关系**;默认可忽略或最低权重 |

**明确**:不把 Obsidian 双链等价宣称为高质量 KG;文档与 README 避免过度承诺。
**明确**:不依赖「用户精心养图」或「软件自动链一切」作为检索正确性来源。

### 3. 质量路线:机器补边优先于强迫用户整理

按优先级(后者依赖前者落地,可分期):

1. **已有** — 向量 / 混合检索保底;`get_links` / tag / 结构工具按需调用
2. **近端(本 ADR 升级主张)** — **检索命中后机会性 1 跳扩邻** + hub 降权 + 引用标注图参与(详见 §3.1)
3. **中期(可选)** — **自动弱边**(共现、同标签粗相关、标题系列等),权重**低于**人工 wikilink;失败无感
4. **远期(可选,非默认)** — 写回建议(「要不要链到 X」)、专题库实体抽(GraphRAG 重路径)— **opt-in**,不进默认全库路径

#### 3.1 近端升级主张(2026-08-03 讨论后钉死)

**主张:** 把「图谱原生」从「能读图的工具」升级为「**检索时默认试一跳、但绝不依赖人先把图养好**」的混合管线 — 向量保下限,双链给增益,噪声 hub 默认挡。

**落地顺序(先小后大):**

| 序 | 内容 | 说明 |
|---|---|---|
| 1 | **1 跳机会性扩邻** | 从向量 top K 命中沿正文 wikilink 出链取邻居;无边静默回退纯向量;**邻居须经语义候选池双通道确认**(链接提议,向量裁决) |
| 2 | **hub / Daily 降权** | 反链数或出链扇出超阈值的节点(Daily Plan、MOC、模板)不进扩邻集 |
| 3 | **边权重分层** | 人工正文链 > 反链 > 标签 > 自动回写链;标签默认只作粗过滤 |
| 4 | **引用标注图参与** | 回答引用区可标注「经链接图补充」的邻居,让用户看见图在起作用 |
| 5 | (中期)自动弱边 | 孤儿/稀疏库兜底;权重低于人工边,可关 |
| 6 | (远期 opt-in)实体 GraphRAG / 写回建议 | 不进默认路径 |

**设计红线:**

- 默认路径**零配置、零「先整理库」步骤**
- 扩邻失败 / 无图 → 结果与今天一致(不劣化)
- Daily / 自动关联 hub **默认视为噪声源**,除非用户显式 opt-in 加深

**明确不作为默认**:

- 强制 orphan 清理流程才能索引 / 对话
- 默认全库 LLM 抽实体建重型 KG(成本、噪声、与双链心智不完全同构)

### 4. 与「图谱原生」总纲的关系

- S-EVOLUTION「向量模糊 + metadataCache 结构精确」**仍然成立**
- 本 ADR 补一句约束:**结构精确是增益通道,不是对人整理度的门禁**
- Phase A 读工具继续有价值:Agent **能**读图;本 ADR 约束的是**产品不要求用户必须先写满图**

### 5. 明确不改动的部分

- 无遥测、网络仅模型 API、ObsidianVault 外观、无原生模块
- 既有权限模型与引用双通道策略
- 用户**自愿**整理链接仍然有益 — 只是不作为硬前提

## Consequences(后果)

### 正面

- 门槛低:乱库 / 新库也能用语义问答
- 话术诚实:双链是杠杆,不装成已建成领域 KG
- 工程可演进:先用现成边,再自动弱边,最后才考虑重型抽图
- 与「少配置、本地优先」品牌一致

### 负面 / 风险

- 链接稀疏时,「图谱原生」体感接近普通 RAG — 需靠引用 UX / 工具能力区分,避免营销空洞
- 自动弱边若做砸会引入噪声 — 必须低于人工边权重,且可关
- Daily hub 自动链若未降权,扩邻会灌入「今日打开过」噪声 — 扩邻实现必须识别 / 降权日记与超高扇出节点
- 重度双链用户可能期待「更吃图」— 可用设置或后续 opt-in 加深扩邻,而非反转默认门禁

### 后续影响

- 新检索 / 扩邻 plan 须遵守本 ADR:默认路径不新增「先整理库」步骤
- 修订对外文案(README / user-guide「图谱」相关句)时,与本 ADR 对齐后再改
- 若未来做实体 GraphRAG,单开 ADR / spec,默认关闭
