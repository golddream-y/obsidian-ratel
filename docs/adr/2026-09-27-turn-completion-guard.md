# ADR-020: 收笔护栏 — 思考已规划、正文过短时再请求一次

**状态**: Accepted
**日期**: 2026-09-27
**关联**:
- [ADR-004](2026-06-27-agent-loop-max-steps.md)（步数上限与 `finish_reason: length` 只提示、不自动续写）

- [S-LOOP-STABILITY](../superpowers/specs/2026-09-26-loop-stability-design.md)（完全空步另续一次）
- [S-COMPACT-V2](../superpowers/archive/S-COMPACT-V2/2026-08-13-compact-v2-design.md)（85% 自动压缩）

## Context（背景）

思考模式把计划写在 `reasoning`，把给用户看的字写在 `content`。接口在模型给出正常结束（`stop`）后就停。循环把「这一步没有工具调用」当成答完。

2026-09-26 的现场是：用户发「继续」，正文只有一行章标题，思考大约一千二百字并准备写四千到五千字，日志是 `ask.end`，存档里没有截断句。正文没有被客户端丢掉，是模型自己收笔。同类现象在 DeepSeek V4 的创作用法里已有公开记录：思考很久，可见正文远短于用户要的篇幅。

只靠用户再打「继续」，稳定性没有下限。别的 Agent 已经把「不该停」做成循环里的护栏，次数封顶：完全没字就再问，进度套话不当成结束，待办没做完就再推一次。`finish_reason: length` 的自动续写是另一类（输出被切断），本次现场不是这类。

现有压缩是估计占用到 **85%** 才把模型看到的历史收成摘要，侧栏不删。这是窗口将满前的最后一道，S-COMPACT-V2 与后续上下文裁剪都维持这个门槛。这场对话压缩没有跑，说明估计占用低于 85%，但日志里没有具体百分比。把门槛改成 50% 没有测量依据，也不能让已经决定停笔的模型把标题写成正文。

DeepSeek 思考模式在请求带 `tools` 时，要求后续轮次把 `reasoning_content` 原样带回，包括没有工具调用的轮次，否则 400。本次不从历史里剥掉思考。

## Decision（决策）

**无工具、正常停笔、可见正文过短而思考更长时，同一轮再请求一次。只给一次。85% 压缩不动。**

### 收笔护栏

在「没有工具调用就结束」之前，同时满足才再请求一次：

1. 结束原因是 `stop`，或流正常结束但没有给出结束原因。取消、接口错误、`length`、`content_filter` 不走这里。
2. 可见正文至少有 1 个码点，且少于 200。完全没有可见字仍归 S-LOOP-STABILITY 的空步。
3. 思考过程的码点严格多于可见正文。
4. 本轮还没有成功的 `write_note` / `edit_note` / `append_note`。
5. 本轮用户消息还没有被这条护栏推过。

不要求用户原文必须是「继续」。问答题若思考很长、回答很短，也会多一次请求。推过一次仍短，就接受这次短回答，不再循环。

再请求前追加一条不落盘的 `system`：`按你刚写的计划，把正文写出来；不要再重列提纲。` 不插入用户气泡。标题与思考照常入库。

### 压缩

维持 `AUTO_COMPACT_THRESHOLD_PCT = 85`，维持现有摘要、`compactMarkers`、断路器与侧栏不删。不新增 50% 触发。包变沉继续靠这道摘要把旧原文换成摘要。

## Consequences（后果）

- 短标题停笔会自动再写一次，用户不必再发「继续」才能看到下一次尝试。
- 简短问答也可能被多问一次。上限是每轮用户消息一次，避免死循环。
- `length` 截断仍只追加提示（ADR-004），不并进这条护栏。
- 历史思考继续回传，避免思考模式 400。请求体积的优化留在 85% 摘要，不靠删 `reasoning`。
