# ADR-024 本地向量推理保持 GPU 优先

- 状态：已接受
- 日期：2026-11-10
- 决策来源：产品负责人确认，优先考虑电脑使用时的响应能力，并覆盖不同 CPU/GPU 配置。
- 相关：[本地 Embedding 运行时策略](2026-06-18-local-embedding-architecture.md)、[嵌入推理分层](../architecture/llm/embedding-inference.md)

## 决定

本地向量推理保持 **GPU 优先，失败自动回退 CPU**。只有 GPU 执行器通过实际推理验证后才投入使用；能够获取 GPU 适配器、能够创建会话，都不足以判定可用。初始化或预热失败时终止该实例，使用独立的 CPU 执行器继续工作。

不因一台高性能 CPU 电脑上的测速差距较小，就将所有用户的默认策略改成 CPU。是否保留或调整 GPU 优先策略，应同时评估索引吞吐、CPU 占用和界面响应，并覆盖不同硬件。

## 为什么保持 GPU 优先

**首先考虑索引期间电脑是否仍然好用。** 索引通常是持续运行的后台任务，用户还要输入、切换笔记和运行其他应用。GPU 推理有机会减少 CPU 上的计算压力，从而降低电脑卡顿的概率。因此，单块推理耗时不是唯一的选型依据。

这是选择 GPU 优先的产品目标，不代表“使用 GPU 一定不卡”。GPU 也需要 CPU 调度，可能与界面渲染争用 GPU，并在部分机器上共享内存与功耗预算。响应性收益必须测量，不能只依据后端名称作保证。

**其次，不同用户的 CPU/GPU 能力并不相同。** 当前验证机器的 CPU 性能较强，CPU 与 GPU 的速度差距不能代表普通笔记本或配备独立 GPU 的电脑。不能将单机结果外推为“GPU 收益有限”，据此移除其他硬件可能受益的执行路径。

## 已有证据与边界

2026-11-10 的验证确认，持续出现的 `Failed to wait for the operation:3` 与新增的外部 GPUDevice 注册路径有关：同机、同模型、同输入下，该路径失败，恢复 ORT 默认设备管理后推理成功。修复后，Obsidian 中 GPU 预热、单条查询和实际索引均有成功记录。这次失败不能用来证明 GPU 硬件不可用或 GPU 方案应被放弃。

独立 Electron 中的固定合成文本对比显示：短查询 CPU 更快，中等批次两者接近，长批次 GPU 有一定优势。该实验不包含完整索引写入，也不是多硬件测试，不能据此承诺固定加速倍数。

此前用 GPU 预热耗时与 CPU 实际索引耗时相除所得的倍数，不作为本决策的性能依据。更早出现的请求超时也不能未经验证就归因为本次设备注册问题。

## 验证与重新评估条件

后续对比使用同一模型、同一批实际笔记块、相同分块与批次配置，并将初始化、预热和稳定运行阶段分别统计。至少比较：

- **吞吐**：总耗时、每块耗时和耗时波动；推理与完整索引分别报告。
- **CPU 占用**：持续索引期间的 CPU 使用情况，以及与其他应用并行工作时的变化。
- **界面响应**：输入、切换笔记等操作的延迟和长任务情况。
- **资源与可靠性**：内存占用、GPU 故障、回退成功率，以及取消和空闲回收行为。

结论只适用于实际测试覆盖的硬件与运行环境。只有代表性硬件上的证据表明 GPU 优先既没有足够的吞吐或响应性收益，又带来不可接受的资源或可靠性成本时，才重新评估默认策略。单次故障或单机 CPU 很快，不足以推翻这一决定。

## 影响

保留 GPU 执行路径和独立 CPU 回退路径。故障修复应针对有证据的原因，不能为了绕过一次查询失败，默认额外常驻另一份推理会话。性能说明必须注明测试范围，不以预热数字代替实际索引表现。
