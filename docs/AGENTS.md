# 文档目录约束

本文件作用于 `docs/` 及其后代。

- 文档主体使用中文，专有名词、代码、路径与协议字段保持原样；新增内容不得包含本机路径或私人库资料。
- 面向人阅读的方案、教程、报告和复盘使用 `human-readable-articles` Skill（可用时）；未提供该 Skill 的 Agent 按文章目标组织内容，不虚构已加载。
- 需求、Issue、spec、plan 和归档相关任务加载根目录的项目管理 Skill。需求文档确认前不以技术候选替代需求，不因文档归档标记功能已交付。
- spec 必须包含背景、目标、非目标、详细设计、影响面、参考；plan 必须包含目标、架构、技术栈、文件结构、任务清单（file/step/code/verification）与自审。
- 新写正文的章节层级不超过三级；更深内容拆文件。既有技术文档的迁移不意味着可以借机重写架构契约。
- 修改 `architecture/` 或 `adr/` 前按开发工作流核对是否已获对应授权；发布记录的写法与发布动作以插件发版 Skill 为准。
- 产品愿景、候选需求和技术方案不得写成当前已交付能力；实际已发布内容以 Release/CHANGELOG 为准。
